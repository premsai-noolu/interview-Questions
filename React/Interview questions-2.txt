1. Tree Shaking:
Tree shaking is a process of removing the unwanted code that
we do not use while developing the application.
In computing, tree shaking is a dead code elimination
technique that is applied when optimizing code.

Example Without Tree Shaking
math.js
export function add(a, b) {
  return a + b;
}

export function subtract(a, b) {
  return a - b;
}

export function multiply(a, b) {
  return a * b;
}

app.js
import { add } from "./math.js";

console.log(add(2, 3));

Here math.js has 3 functions:
add
subtract
multiply

But in app.js we are only using add().

What Happens Without Tree Shaking
The bundle will include all functions:

add()
subtract()
multiply()

Even though only add() is used.
This makes the bundle larger.

What Happens With Tree Shaking
During build (Webpack/Vite production build):
Unused functions are removed.
Final bundle will contain only:

function add(a, b) {
  return a + b;
}
console.log(add(2, 3));

subtract() and multiply() are removed.
This reduces bundle size.

2. Optional Chaining (?.) is a JavaScript feature used in React (and JavaScript) to safely access nested object properties without causing errors if something is null or undefined.

Problem Without Optional Chaining

Consider this object:

const user = {
  profile: {
    name: "Prem"
  }
};

If you try to access:
console.log(user.profile.name);
✅ Works fine.

But if profile is undefined:

const user = {};
console.log(user.profile.name);

❌ Error:
Cannot read property 'name' of undefined
Solution: Optional Chaining

Using ?.

console.log(user.profile?.name);

Now if profile is undefined:
✅ It does not throw an error
It returns undefined.

React Example (Very Common)

In React we often get data from APIs.
Example API response:

const restaurant = {
  info: {
    name: "Pizza Hut"
  }
};

Accessing data:
restaurant.info.name

But sometimes API data is not loaded yet.

So we use:
restaurant?.info?.name

This prevents the app from crashing.

Example in React Component
function RestaurantCard({ data }) {
  return (
    <div>
      <h2>{data?.info?.name}</h2>
      <p>{data?.info?.rating}</p>
    </div>
  );
}

If data or info is missing, React won’t throw an error.

How It Works
object?.property

Meaning:
If object exists → access property
If object is null/undefined → return undefined

Interview Definition
Optional chaining (?.) is a JavaScript feature that allows safe access to nested object properties without throwing errors if an intermediate property is null or undefined.

3. Q ) How will useEffect behave if we don't add a
dependency array?

1️⃣ Without Dependency Array
If no dependency array is provided, useEffect runs after every render of the component.
Runs after initial render
Runs after every re-render

useEffect(() => {
  console.log("Effect executed");
});

👉 Example: If state changes and component re-renders, the effect runs again.

2️⃣ Empty Dependency Array []
If the dependency array is empty, the effect runs only once after the initial render.

useEffect(() => {
  console.log("Effect executed");
}, []);

Runs only once
Similar to componentDidMount in class components.

⚠️ Note: It will run again only if the component unmounts and mounts again.

3️⃣ With Dependencies [value]
If you pass variables in the dependency array, the effect runs:
After initial render
Whenever those dependencies change

useEffect(() => {
  console.log("Effect executed");
}, [count]);

👉 Runs again only when count changes.

✅ One-line interview answer:
In React, useEffect without a dependency array runs after every render, with an empty array it runs only once after the initial render, and with dependencies it runs after the initial render and whenever those dependencies change.

4. 📌 What is SPA in React?

SPA (Single Page Application) is a type of web application that loads a single HTML page once and then dynamically updates the content without reloading the entire page.

⚛️ In React:
React is commonly used to build SPAs where:
Only one HTML file is loaded (index.html)
Navigation between pages happens using JavaScript (client-side routing)
UI updates happen without full page refresh

🔄 How it works:
When you click a link (e.g., Home → About)
React updates only the required component
The browser does NOT reload the page

🧠 Example:
Using React Router:
<Route path="/about" element={<About />} />

👉 Clicking /about loads the About component without refreshing the page

🚀 Advantages:

Faster performance ⚡
Smooth user experience (no reloads)
Less server load
Feels like a mobile app

⚠️ Disadvantages:

Initial load can be heavy
SEO can be tricky (needs SSR or tools)
More complex state management

✅ One-line interview answer:
A Single Page Application (SPA) in React is a web app that loads a single HTML page and dynamically updates content using client-side routing without reloading the page.

5. 📌 Order of Lifecycle Methods (Class Components)

🔄 Mounting Phase (when component is created)
constructor()
render()
componentDidMount()

🔁 Updating Phase (when state/props change)
render()
componentDidUpdate()

❌ Unmounting Phase (when component is removed)
componentWillUnmount()

🧠 Simple Example
import React from "react";

class MyComponent extends React.Component {
  constructor(props) {
    super(props);
    console.log("1. Constructor called");
    this.state = { count: 0 };
  }

  componentDidMount() {
    console.log("3. Component Did Mount");
  }

  componentDidUpdate() {
    console.log("5. Component Did Update");
  }

  componentWillUnmount() {
    console.log("6. Component Will Unmount");
  }

  render() {
    console.log("2. Render called");
    return (
      <div>
        <h2>Count: {this.state.count}</h2>
        <button onClick={() => this.setState({ count: this.state.count + 1 })}>
          Increment
        </button>
      </div>
    );
  }
}

export default MyComponent;

🔍 What happens step-by-step?
🟢 Initial Load (Mounting)
1. Constructor called
2. Render called
3. Component Did Mount
🔵 When Button is Clicked (Update)
4. Render called
5. Component Did Update
🔴 When Component is Removed
6. Component Will Unmount

🎯 Key Understanding
constructor → initialize state
render → returns UI (JSX)
componentDidMount → API calls / setup
componentDidUpdate → reacts to updates
componentWillUnmount → cleanup (timers, subscriptions)

✅ One-line Interview Answer:
In class components, lifecycle order is: constructor → render → componentDidMount (mounting), then render → componentDidUpdate (updating), and finally componentWillUnmount during unmounting.

6. 📌 Why do we use componentDidMount?
🟢 Definition
componentDidMount is called once after the component is added to the DOM.

🎯 Why we use it?
👉 Because at this point:
The component is fully loaded in the DOM
It is safe to perform side effects

🔥 Common Uses
API Calls (Most Important)
DOM Manipulation
Starting timers / subscriptions

🧠 Example (API Call)
componentDidMount() {
  fetch("https://api.example.com/data")
    .then(res => res.json())
    .then(data => {
      this.setState({ data });
    });
}

👉 Data is fetched after UI is rendered once
✅ One-line Interview Answer:
componentDidMount is used to perform side effects like API calls after the component is mounted to the DOM.

7. 📌 Why do we use componentWillUnmount?
🔴 Definition
componentWillUnmount is called just before the component is removed from the DOM.

🎯 Why we use it?
👉 To clean up things created earlier
🔥 Common Uses
Remove event listeners
Clear timers (setInterval / setTimeout)
Cancel API requests
Cleanup subscriptions

🧠 Example (Event Listener Cleanup)
componentDidMount() {
  window.addEventListener("resize", this.handleResize);
}

componentWillUnmount() {
  window.removeEventListener("resize", this.handleResize);
}
⚠️ Why cleanup is important?
❌ Without cleanup:
Memory leaks
Duplicate event calls
Performance issues

🧠 Simple Analogy

componentDidMount → Start / Setup 🟢
componentWillUnmount → Stop / Cleanup 🔴

👉 Like:
Start music when entering a room 🎵
Stop music when leaving 🚪

🔁 Flow Together
Mount → componentDidMount (start things)
Unmount → componentWillUnmount (stop things)
✅ One-line Interview Answer:
componentWillUnmount is used to clean up resources like event listeners, timers, or subscriptions before a component is removed from the DOM.

🎯 Final Interview Tip
👉 Always say this line (very impactful):
“We start side effects in componentDidMount and clean them up in componentWillUnmount to avoid memory leaks.”

8. 📌 Why do we use super(props) in constructor?
🧠 Core Idea
When a class extends another class, it must call the parent class constructor.

👉 In React:
MyComponent extends React.Component
So we must call parent constructor → super()

🔥 Why specifically super(props)?
✅ 1. Calls Parent (React.Component) Constructor
super(props);

👉 This ensures React sets up:
this.props
Component internals

✅ 2. Makes this.props Available in Constructor
❌ Without super(props)
constructor(props) {
  super();
  console.log(this.props); // ❌ undefined
}
✅ With super(props)
constructor(props) {
  super(props);
  console.log(this.props); // ✅ works
}
✅ 3. Required Before Using this

👉 JavaScript rule:
You cannot use this in a child class constructor until super() is called

❌ Wrong
constructor(props) {
  this.state = {}; // ❌ Error
  super(props);
}
✅ Correct
constructor(props) {
  super(props);
  this.state = {}; // ✅
}

🧠 Simple Analogy
React.Component → Parent 👨
MyComponent → Child 👶

👉 Before child uses anything (this),
it must call parent → super(props)

🧩 Full Example
class MyComponent extends React.Component {
  constructor(props) {
    super(props); // Step 1: call parent constructor
    this.state = { count: 0 }; // Step 2: initialize state
  }

  render() {
    return <h1>{this.props.name}</h1>;
  }
}

⚡ Important Note (Interview Trick)
👉 If you don’t define a constructor, React handles it internally.
👉 You only need super(props) when:

You write your own constructor

✅ One-line Interview Answer:
super(props) is used to call the parent (React.Component) constructor so that this.props is initialized and we can use this inside the constructor.

🎯 Best Interview Closing Line
Without calling super(props), we cannot access this.props or use this inside the constructor.

9. ✅ Why can’t the useEffect callback be async?

In React, the callback function passed to useEffect cannot be async because of how React handles its return value.

🔑 Core Reason
1. Return Type Mismatch

useEffect expects the callback to return
Nothing (undefined), OR
A cleanup function

useEffect(() => {
  return () => {
    // cleanup
  };
}, []);

But an async function always returns a Promise

useEffect(async () => {
  // ❌ This returns a Promise, not a cleanup function
});

👉 React cannot treat a Promise as a cleanup function → breaks expected behavior

2. Cleanup Handling Problem

React uses the returned function to:
Clean up subscriptions
Cancel timers
Avoid memory leaks

If the callback is async:
React gets a Promise instead of a function
It doesn’t know when or how to run cleanup

3. Execution & Lifecycle Control

React needs synchronous control over:
When effects run
When cleanup happens

Async functions introduce:
Delayed execution
Unpredictable timing

👉 This makes lifecycle management unreliable

✅ Correct Pattern (Recommended Way)
Instead of making useEffect async, define an async function inside it:

useEffect(() => {
  const fetchData = async () => {
    try {
      const result = await fetch("/api/data");
      const data = await result.json();
      setData(data);
    } catch (error) {
      console.error(error);
    }
  };

  fetchData();

  return () => {
    // cleanup if needed
  };
}, []);

🎯 Interview One-Liner
👉 “We cannot make useEffect async because it must return either a cleanup function or nothing, but async functions return a Promise, which React cannot use for cleanup.”
