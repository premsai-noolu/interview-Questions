🔥 SQL Interview Questions (Must-Prepare)
🟢 Basics (Very Important)

1. What is SQL?

SQL (Structured Query Language) is a standard language used to communicate with relational databases. It allows us to store, retrieve, update, delete, and manage data in a database.

With SQL, you can:

Create database structures (tables, indexes, views)
Insert, update, and delete data
Retrieve data using queries
Control user access and permissions
Manage transactions

2. Difference between DDL, DML, DCL, TCL

🔹 DDL – Data Definition Language
Purpose: Defines and modifies the structure of database objects

Commands:
CREATE
ALTER
DROP
TRUNCATE
RENAME

Example:

CREATE TABLE Employee (
  id INT PRIMARY KEY,
  name VARCHAR(50)
);

👉 DDL affects schema, not the data itself.

🔹 DML – Data Manipulation Language
Purpose: Used to insert, update, delete, and retrieve data

Commands:
INSERT
UPDATE
DELETE
SELECT

Example:

UPDATE Employee
SET salary = 60000
WHERE id = 101;

👉 DML works on data inside tables.

🔹 DCL – Data Control Language
Purpose: Controls access and permissions to database objects

Commands:
GRANT
REVOKE

Example:

GRANT SELECT ON Employee TO user1;

👉 It gives permission to user1 to read data from the Employee table.user1 can run SELECT queries on the Employee table, but cannot insert, update, or delete data.
👉 DCL ensures security.

🔹 TCL – Transaction Control Language

Purpose: Manages transactions and maintains data consistency

Commands:

COMMIT
ROLLBACK
SAVEPOINT

Example:

SAVEPOINT sp1;
ROLLBACK TO sp1;
COMMIT;

Explanation of Each Statement
🔹 SAVEPOINT sp1;

Creates a checkpoint inside a transaction
Lets you partially roll back without losing everything

Think of it as:
“Remember this position so I can come back here if needed.”

🔹 ROLLBACK TO sp1;

Undoes all changes made after sp1
Keeps all changes before sp1

👉 Only partial rollback, not full rollback.

🔹 COMMIT;

Permanently saves the current state of the transaction
After COMMIT, changes cannot be undone

Real Example (Very Important)
BEGIN;
INSERT INTO Employee VALUES (1, 'Tony', 50000);
SAVEPOINT sp1;
INSERT INTO Employee VALUES (2, 'Steve', 60000);
ROLLBACK TO sp1;
COMMIT;

Final Result in Table:

✅ Tony is inserted
❌ Steve is NOT inserted

Because:

ROLLBACK TO sp1 removed Steve
COMMIT saved Tony permanently

👉 TCL ensures ACID properties.

3. Difference between DELETE, TRUNCATE, DROP

🔹 DELETE
Purpose: Removes specific rows or all rows from a table

Key Points

Can use WHERE clause
Row-by-row operation
Can be rolled back (if not committed)
Table structure remains

Example
DELETE FROM Employee WHERE dept = 'HR';

🔹 TRUNCATE
Purpose: Removes all rows from a table at once

Key Points

WHERE clause ❌ not allowed
Faster than DELETE
Cannot be rolled back (in most DBs)
Resets auto-increment
Table structure remains

Example
TRUNCATE TABLE Employee;

🔹 DROP
Purpose: Deletes the entire table structure

Key Points

Removes data + structure
Cannot be rolled back
Frees storage space
Table no longer exists

Example
DROP TABLE Employee;

4. What is a primary key?

A primary key is a column (or combination of columns) in a table that uniquely identifies each row in that table.

Key Characteristics (Very Important for Interviews)

✅ Unique – no two rows can have the same value
❌ Cannot be NULL – every row must have a value
📌 Only one primary key per table
⚡ Automatically creates an index (in most databases)

Simple Example
CREATE TABLE Employee (
  emp_id INT PRIMARY KEY,
  name VARCHAR(50),
  salary INT
);


Here:

emp_id uniquely identifies each employee
No duplicate or NULL values allowed in emp_id

Composite Primary Key:
A primary key can consist of multiple columns.
PRIMARY KEY (order_id, product_id)

Used when a single column is not enough to ensure uniqueness.

A primary key uniquely identifies each record in a table and does not allow duplicate or NULL values.

5. Difference between primary key and unique key

🔑 Primary Key
Purpose: Uniquely identifies each row in a table

Key Points
Only one primary key per table
Does NOT allow NULL values
Automatically creates an index
Ensures entity integrity

Example
CREATE TABLE Employee (
  emp_id INT PRIMARY KEY,
  email VARCHAR(100) UNIQUE
);

🔑 Unique Key
Purpose: Ensures uniqueness of a column

Key Points
Multiple unique keys allowed per table
Allows one NULL value (DB-dependent)
Automatically creates an index
Ensures data uniqueness

A primary key uniquely identifies a record and does not allow NULLs, whereas a unique key only enforces uniqueness and can allow NULL values.

6. What is a foreign key?

A foreign key is a column (or set of columns) in one table that refers to the primary key (or unique key) of another table.
It is used to maintain a relationship between tables and ensure referential integrity.

Simple Example
CREATE TABLE Department (
  dept_id INT PRIMARY KEY,
  dept_name VARCHAR(50)
);

CREATE TABLE Employee (
  emp_id INT PRIMARY KEY,
  name VARCHAR(50),
  dept_id INT,
  FOREIGN KEY (dept_id) REFERENCES Department(dept_id)
);

Department.dept_id → Primary Key
Employee.dept_id → Foreign Key

👉 Every dept_id in Employee must exist in Department.

Key Characteristics (Interview Important)
Can have duplicate values
Can allow NULL values
Enforces referential integrity
Prevents invalid data insertion

What Foreign Key Prevents
❌ Inserting an employee with a non-existing department

Example (Very Clear)

Parent Table
Department
-----------
dept_id
---------
10
20
30

Child Table
Employee
-----------
emp_id | dept_id

Here:

Employee.dept_id is a foreign key
It references Department.dept_id

❌ Invalid Data Insertion (Blocked)
INSERT INTO Employee (emp_id, dept_id)
VALUES (1, 99);

❌ Error occurs because:
dept_id = 99 does NOT exist in Department
👉 This is invalid data, and the foreign key prevents it.

👉 It means:

8. What is constraint? Name different constraints

A constraint is a rule applied to a table or column to restrict the type of data that can be stored in it.
Constraints help maintain data accuracy, consistency, and integrity in a database.

🔑 Different Types of Constraints (Very Important)
1️⃣ NOT NULL

Ensures a column cannot have NULL values
name VARCHAR(50) NOT NULL

2️⃣ UNIQUE

Ensures all values are unique
email VARCHAR(100) UNIQUE

3️⃣ PRIMARY KEY

Uniquely identifies each row
(No duplicates, no NULLs)
id INT PRIMARY KEY

4️⃣ FOREIGN KEY

Creates a relationship between tables
Prevents invalid data insertion
FOREIGN KEY (dept_id) REFERENCES Department(dept_id)

5️⃣ CHECK

Restricts values based on a condition
age INT CHECK (age >= 18)

6️⃣ DEFAULT

Assigns a default value if none is provided
status VARCHAR(20) DEFAULT 'Active'


9. What is index? Why do we use it?

An index is a database object that improves the speed of data retrieval (SELECT queries) on a table by allowing the database to find rows quickly without scanning the entire table.

🔍 Why do we use Indexes?
1️⃣ Faster SELECT Queries

Without index:

Database performs full table scan
Slower for large tables

With index:

Database uses index lookup
Much faster search

3️⃣ Enforces Uniqueness (Sometimes)

PRIMARY KEY and UNIQUE constraints create indexes automatically.

Example:

Without Index (Slow Query)
Table: Employee
emp_id	name	salary
1	A	30000
2	B	40000
3	C	50000
...	...	...
100000	Z	80000
Query
SELECT *
FROM Employee
WHERE salary = 50000;

What happens?

Database checks each row one by one
This is called a full table scan

❌ Slow when table is large

Create Index
CREATE INDEX idx_salary ON Employee(salary);

With Index (Fast Query)
Now run the same query:

Database looks into index structure
Directly jumps to rows with salary = 50000
🚀 Much faster

1️⃣ INNER JOIN
What is INNER JOIN?

Returns only the matching rows from both tables.

Example Tables

Employee

emp_id	name	dept_id
1	Tony	10
2	Steve	20
3	Bruce	30

Department

dept_id	dept_name
10	     IT
20 	     HR
Query
SELECT e.name, d.dept_name
FROM Employee e
INNER JOIN Department d
ON e.dept_id = d.dept_id;

Output
name	dept_name
Tony	IT
Steve	HR

👉 Bruce is excluded because dept_id 30 has no match

Interview One-Liner ⭐
INNER JOIN returns only records that have matching values in both tables.

2️⃣ LEFT JOIN (LEFT OUTER JOIN)
What is LEFT JOIN?

Returns:

All rows from left table
Matching rows from right table
NULL if no match

Query
SELECT e.name, d.dept_name
FROM Employee e
LEFT JOIN Department d
ON e.dept_id = d.dept_id;

Output
name	dept_name
Tony	IT
Steve	HR
Bruce	NULL

👉 Bruce is included because LEFT JOIN keeps all left table records

Interview One-Liner ⭐
LEFT JOIN returns all rows from the left table and matching rows from the right table.

🔍 Difference: INNER JOIN vs LEFT JOIN
Matching rows	   Only matching	    All left rows
Non-matching rows	Excluded	       Included with NULL
Use case	     Strict matching	     Find missing records

3️⃣ RIGHT JOIN (RIGHT OUTER JOIN)
What is RIGHT JOIN?

Returns:
All rows from right table
Matching rows from left table
NULL if no match

Query
SELECT e.name, d.dept_name
FROM Employee e
RIGHT JOIN Department d
ON e.dept_id = d.dept_id;

Output
name	dept_name
Tony	IT
Steve	HR

(If Department had extra rows, they would appear with NULL employee)

📌 Interview Tip:
RIGHT JOIN can always be rewritten using LEFT JOIN.

🔗 FULL JOIN (FULL OUTER JOIN)

A FULL JOIN returns:

All matching rows
All non-matching rows from the LEFT table
All non-matching rows from the RIGHT table

👉 If there is no match on either side, the missing columns are filled with NULL.

4️⃣ SELF JOIN
What is SELF JOIN?

A table joined with itself.
Used when rows in a table are related to other rows in the same table.

Example Table: Employee
emp_id	name	manager_id
1	    Tony	NULL
2	    Steve	1
3	    Bruce	1
Query
SELECT e.name AS Employee, m.name AS Manager
FROM Employee e
LEFT JOIN Employee m
ON e.manager_id = m.emp_id;

Output
Employee	Manager
Tony	NULL
Steve	Tony
Bruce	Tony
Interview One-Liner ⭐
SELF JOIN is used to join a table with itself using aliases.

5️⃣ CROSS JOIN
What is CROSS JOIN?

Returns Cartesian product:
Every row from table A
Combined with every row from table B

Example

Table A → 2 rows
Table B → 3 rows

👉 Result = 2 × 3 = 6 rows

Query:
SELECT *
FROM A
CROSS JOIN B;

Use Case

Creating combinations
Generating test data

Interview One-Liner ⭐
CROSS JOIN returns all possible combinations of rows from both tables.

11. Write a query to fetch records present in table A but not in table B

👉 Fetch records present in Table A but NOT in Table B

Example Tables
TableA (Employees)
id	name
1	Tony
2	Steve
3	Bruce
4	Peter
TableB (Employees on Project)
id
1
3
Expected Output

Employees present in TableA but not in TableB

id	name
2	Steve
4	Peter
✅ Best Query (Interview Preferred)
SELECT A.*
FROM TableA A
LEFT JOIN TableB B
  ON A.id = B.id
WHERE B.id IS NULL;

How This Query Works (Explain Like This in Interview)
Step 1: LEFT JOIN
FROM TableA A
LEFT JOIN TableB B
ON A.id = B.id;

Result after join:

A.id	A.name	B.id
1	Tony	1
2	Steve	NULL
3	Bruce	3
4	Peter	NULL

All rows from TableA are kept

Matching rows from TableB are joined

Non-matching rows get NULL in B.id

Step 2: Filter NULLs
WHERE B.id IS NULL;

This filters rows where:

There is no matching record in TableB

Final Output:

id	name
2	Steve
4	Peter

⭐ Interview One-Liner Answer

By using a LEFT JOIN and filtering rows where the right table’s key is NULL, we can fetch records present in Table A but not in Table B.

12. Difference between WHERE and HAVING

Let’s explain WHERE vs HAVING with a very clear example, step by step, exactly how you can say it in an interview.

Example Table: Employee
emp_id	name	dept	salary
1	Tony	IT	60000
2	Steve	IT	55000
3	Bruce	HR	40000
4	Natasha	HR	45000
5	Peter	HR	70000
🔹 WHERE Example (Row-level filtering)
Question:

👉 Get employees whose salary is greater than 50,000

SELECT *
FROM Employee
WHERE salary > 50000;

How it works:

SQL checks each row
Filters rows before grouping

Output:
emp_id	name	dept	salary
1	Tony	IT	60000
2	Steve	IT	55000
5	Peter	HR	70000

🔹 HAVING Example (Group-level filtering)
Question:

👉 Get departments whose average salary is greater than 55,000

SELECT dept, AVG(salary)
FROM Employee
GROUP BY dept
HAVING AVG(salary) > 55000;

How it works:

Rows are grouped by dept
AVG(salary) is calculated per group
HAVING filters the groups

Output:
dept	avg_salary
IT	    57500
❌ Why WHERE Cannot Replace HAVING
WHERE AVG(salary) > 55000; -- ❌ INVALID

Because:

WHERE runs before GROUP BY
Aggregate functions are not available yet

🔁 Using WHERE and HAVING Together
Question:
👉 Departments with more than 1 employee earning above 45,000

SELECT dept, COUNT(*)
FROM Employee
WHERE salary > 45000
GROUP BY dept
HAVING COUNT(*) > 1;

Explanation:

WHERE → filters employees first
GROUP BY → groups remaining rows
HAVING → filters groups

⭐ Interview One-Liner
WHERE filters individual rows before grouping, while HAVING filters aggregated groups after GROUP BY.

🧠 Easy Way to Remember

WHERE = row filter
HAVING = group filter

13. Difference between GROUP BY and ORDER BY

GROUP BY:

Used to group rows that have the same values
Commonly used with aggregate functions (COUNT, SUM, AVG, MAX, MIN)
Reduces multiple rows into one row per group

Example

👉 Find total salary per department

SELECT dept, SUM(salary) AS total_salary
FROM Employee
GROUP BY dept;

How it works:

Rows are grouped by dept
SUM(salary) is calculated per group

Sample Output
dept	total_salary
IT	115000
HR	155000

🔹 ORDER BY
What is ORDER BY?

Used to sort the result set
Does not change number of rows
Can sort in ASC (default) or DESC

Example

👉 List employees sorted by salary

SELECT *
FROM Employee
ORDER BY salary DESC;

Sample Output
name	salary
Peter	70000
Tony	60000
Steve	55000
Natasha	45000
Bruce	40000

🔁 Using GROUP BY and ORDER BY Together
SELECT dept, AVG(salary) AS avg_salary
FROM Employee
GROUP BY dept
ORDER BY avg_salary DESC;

👉 Groups first, then sorts the grouped results.

⭐ Interview One-Liner
GROUP BY groups rows to apply aggregate functions, while ORDER BY sorts the final result set.

🧠 Easy Way to Remember
GROUP BY → combine rows
ORDER BY → arrange rows

14. What are aggregate functions?

Aggregate functions are built-in SQL functions that perform calculations on multiple rows and return a single summarized value.

They are commonly used with the GROUP BY clause.

🔑 Common Aggregate Functions (Very Important)
1️⃣ COUNT()

Returns the number of rows
SELECT COUNT(*) FROM Employee;

COUNT(*) → counts all rows
COUNT(column) → ignores NULL values

2️⃣ SUM()

Returns the total of numeric values
SELECT SUM(salary) FROM Employee;

3️⃣ AVG()

Returns the average value
SELECT AVG(salary) FROM Employee;

4️⃣ MAX()

Returns the highest value
SELECT MAX(salary) FROM Employee;

5️⃣ MIN()

Returns the lowest value
SELECT MIN(salary) FROM Employee;

🧠 Example Table: Employee
emp_id	dept	salary
1	IT	60000
2	IT	55000
3	HR	40000
4	HR	45000
Aggregate + GROUP BY Example

👉 Average salary per department

SELECT dept, AVG(salary) AS avg_salary
FROM Employee
GROUP BY dept;

Output
dept	avg_salary
IT	57500
HR	42500
Important Rules (Interview Favorites)

Aggregate functions ignore NULL values (except COUNT(*))
Cannot use aggregate functions in WHERE
Must use HAVING for conditions on aggregates

❌ Wrong:

WHERE AVG(salary) > 50000

✅ Correct:

HAVING AVG(salary) > 50000

Example

👉 Returns the total number of rows

🔢 COUNT(column)

Counts only non-NULL values in a specific column
Ignores NULL values

Example

👉 Counts only rows where salary is NOT NULL

🧠 Example Table: Employee

16. What is COALESCE()?

COALESCE() is a SQL function used to replace NULL values.
It returns the first non-NULL value from the list of arguments.

COALESCE(value1, value2, ..., valueN)

👉 SQL checks values from left to right and returns the first one that is NOT NULL.

Simple Example
SELECT COALESCE(NULL, NULL, 5000);

Output
5000

Real Example (Very Important)
Employee Table
emp_id	name	salary	bonus
1	Tony	60000	NULL
2	Steve	NULL	5000
Query
SELECT name,
       COALESCE(salary, bonus, 0) AS final_amount
FROM Employee;

Output
name	final_amount
Tony	60000
Steve	5000
Why do we use COALESCE?

Handle NULL values
Avoid calculation errors
Display meaningful default values

16. What is a subquery?

A subquery is a query written inside another SQL query.
It is used to provide intermediate results that the main (outer) query uses to complete its task.

👉 In simple words:

A subquery is a query within a query.
Where Can Subqueries Be Used?

Subqueries can be used in:

WHERE clause
SELECT clause
FROM clause
HAVING clause

Simple Example
Find employees earning more than the average salary
SELECT *
FROM Employee
WHERE salary > (
    SELECT AVG(salary)
    FROM Employee
);

How it works:

Inner query calculates average salary
Outer query fetches employees with salary greater than that average

Example Table: Employee
emp_id	name	salary
1	Tony	60000
2	Steve	50000
3	Bruce	40000
Average salary = 50,000

👉 Output:

emp_id	name	salary
1	Tony	60000
Types of Subqueries (Interview Important)

1️⃣ Single-row subquery
Returns one value

WHERE salary = (SELECT MAX(salary) FROM Employee)

2️⃣ Multi-row subquery
Returns multiple values

WHERE dept_id IN (SELECT dept_id FROM Department)

17. Difference between correlated and non-correlated subquery

🔹 Non-Correlated Subquery
A non-correlated subquery is a subquery that runs independently of the outer query.
Executes once
Result is passed to the outer query
Easier to understand and faster

Example

👉 Employees earning more than average salary

SELECT *
FROM Employee
WHERE salary > (
    SELECT AVG(salary)
    FROM Employee
);

How it works:

Inner query calculates average salary
Outer query compares each employee’s salary to that value

🔹 Correlated Subquery
A correlated subquery depends on the outer query.

Executes once for each row of the outer query
Uses values from the outer query
Slower but more powerful

Example

👉 Employees earning more than the average salary of their department

SELECT *
FROM Employee e
WHERE salary > (
    SELECT AVG(salary)
    FROM Employee
    WHERE dept_id = e.dept_id
);

How it works:

For each employee, the subquery calculates department-wise average
Then compares employee salary with it

🧠 Example Table
emp_id	name	dept	salary
1	Tony	IT	60000
2	Steve	IT	50000
3	Bruce	HR	40000
4	Natasha	HR	45000
Output of Correlated Query
name	dept	salary
Tony	IT	60000
Natasha	HR	45000

⭐ Interview One-Liner
A non-correlated subquery runs independently, while a correlated subquery depends on the outer query and executes once per row.

18. Find 2nd / 3rd / 5th highest salary

3️⃣ 3rd Highest Salary
SELECT salary
FROM (
    SELECT salary,
           DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM Employee
) t
WHERE rnk = 3;

👉 It finds the 3rd highest DISTINCT salary from the Employee table.

Step-by-Step Explanation
🔹 Step 1: Inner Query (Window Function)
SELECT salary,
       DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
FROM Employee;

What happens here?

ORDER BY salary DESC → sorts salaries from highest to lowest

DENSE_RANK():

Assigns a rank to each distinct salary
Same salaries get the same rank
No gaps in ranking

🔹 Example Data
emp_id	salary
1	100000
2	90000
3	90000
4	80000
5	70000
🔹 Result of Inner Query
salary	rnk
100000	1
90000	2
90000	2
80000	3
70000	4
🔹 Step 2: Outer Query (Filtering)
WHERE rnk = 3;

Filters rows where rank is 3
Returns the 3rd highest distinct salary

Final Output
80000

✅ METHOD 2: Using LIMIT & OFFSET (MySQL / PostgreSQL)
SELECT DISTINCT salary
FROM Employee
ORDER BY salary DESC
LIMIT 1 OFFSET 1;   -- 2nd highest

LIMIT 1 OFFSET 2;   -- 3rd highest
LIMIT 1 OFFSET 4;   -- 5th highest

19. Find duplicate records in a table

Example Data
emp_id	name	email	salary
1	Tony	tony@gmail.com
	60000
2	Steve	steve@gmail.com
	55000
3	Tony	tony@gmail.com
	60000
4	Bruce	bruce@gmail.com
	40000
5	Tony	tony@gmail.com
	60000

Here, Tony’s record is duplicated.

✅ Method 1: Using GROUP BY + HAVING (Most Common)
Find duplicate rows based on a column (e.g., email)
SELECT email, COUNT(*) AS cnt
FROM Employee
GROUP BY email
HAVING COUNT(*) > 1;

Output
email	cnt
tony@gmail.com
	3

👉 Shows which values are duplicated

✅ Method 2: Fetch the FULL duplicate records
SELECT *
FROM Employee
WHERE email IN (
    SELECT email
    FROM Employee
    GROUP BY email
    HAVING COUNT(*) > 1
);

Output

All rows where email = 'tony@gmail.com'

✅ Method 3: Find duplicates using multiple columns
SELECT name, email, salary, COUNT(*)
FROM Employee
GROUP BY name, email, salary
HAVING COUNT(*) > 1;

👉 Finds exact duplicate rows

🧠 How to Explain in Interview (Simple)
We can find duplicate records using GROUP BY on the required column(s) and filter groups having COUNT(*) > 1 using HAVING.

20. Delete duplicate records (keep one)
The Query
DELETE FROM Employee
WHERE emp_id NOT IN (
    SELECT MIN(emp_id)
    FROM Employee
    GROUP BY email
);

What does this query do?

👉 It deletes duplicate records from the Employee table
👉 Keeps only one record per email
👉 Specifically, it keeps the row with the smallest emp_id for each email

Example Table (Before)
emp_id	name	email
1	Tony	tony@gmail.com

2	Steve	steve@gmail.com

3	Tony	tony@gmail.com

4	Bruce	bruce@gmail.com

5	Tony	tony@gmail.com

Here:

tony@gmail.com appears 3 times

Step-by-Step Execution
🔹 Step 1: Inner Query
SELECT MIN(emp_id)
FROM Employee
GROUP BY email;

Result of inner query:
email	MIN(emp_id)
tony@gmail.com
	1
steve@gmail.com
	2
bruce@gmail.com
	4

👉 These are the records we want to KEEP

🔹 Step 2: Outer DELETE
DELETE FROM Employee
WHERE emp_id NOT IN (1, 2, 4);

👉 This deletes:

emp_id = 3
emp_id = 5

22. Difference between ROW_NUMBER(), RANK(), DENSE_RANK()

These are window (ranking) functions used to assign a rank to rows based on an order.

Example Table: Employee
emp_id	name	salary
1	Tony	100000
2	Steve	90000
3	Bruce	90000
4	Natasha	80000
5	Peter	70000
Query Used
SELECT name, salary,
       ROW_NUMBER() OVER (ORDER BY salary DESC) AS row_num,
       RANK() OVER (ORDER BY salary DESC) AS rnk,
       DENSE_RANK() OVER (ORDER BY salary DESC) AS dense_rnk
FROM Employee;

Output
name	salary	ROW_NUMBER	RANK	DENSE_RANK
Tony	100000	1	1	1
Steve	90000	2	2	2
Bruce	90000	3	2	2
Natasha	80000	4	4	3
Peter	70000	5	5	4
Key Differences Explained
🔹 ROW_NUMBER()

Assigns unique number to each row
Does not care about duplicates
Always increments by 1
👉 Use when you need unique row IDs

🔹 RANK()

Same values get same rank
Skips ranks after duplicates
👉 Use when ranking positions matter (like competition ranking)

🔹 DENSE_RANK()

Same values get same rank
Does NOT skip ranks
👉 Best for Nth highest salary

24. SQL Order of Execution (Sequence of Operations)

SQL executes queries in a logical order starting from FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT, not in the written order.

This is a very important interview question 👍

25. Find top 3 salaries in each department

Query
SELECT emp_id, name, department, salary
FROM (
    SELECT
        emp_id,
        name,
        department,
        salary,
        DENSE_RANK() OVER (
            PARTITION BY department
            ORDER BY salary DESC
        ) AS rnk
    FROM Employee
) t
WHERE rnk <= 3;

🔹 Step-by-Step SQL Execution
1️⃣ INNER QUERY – FROM Employee
FROM Employee

SQL first reads all rows from the Employee table

No filtering yet

📌 At this point:

All employees are loaded

2️⃣ WINDOW FUNCTION EXECUTION
DENSE_RANK() OVER (
    PARTITION BY department
    ORDER BY salary DESC
)

This happens after FROM and before WHERE of the outer query.

What SQL does internally:

Partitions data by department
Sorts each department by salary DESC
Assigns rank starting from 1 in each department
Same salary → same rank
No gaps in ranking (because DENSE_RANK)

📌 Example (IT department):

Salary: 90000 → rnk = 1
Salary: 85000 → rnk = 2
Salary: 85000 → rnk = 2
Salary: 70000 → rnk = 3

3️⃣ INNER SELECT List Execution
SELECT emp_id, name, department, salary, rnk

SQL now creates a temporary result set
This result includes the calculated rnk

Temporary Table (t)
emp_id	name	department	salary	rnk
1	A	IT	90000	1
2	B	IT	85000	2
3	C	IT	85000	2
4	D	IT	70000	3
5	E	HR	80000	1
6	F	HR	75000	2
7	G	HR	72000	3

📌 This result is aliased as t

4️⃣ OUTER QUERY – FROM t
FROM ( ... ) t

SQL treats the inner query as a derived table
Now all filtering happens on this result

5️⃣ OUTER WHERE CLAUSE
WHERE rnk <= 3

SQL filters rows after ranking is completed
Keeps only top 3 salaries per department

📌 Important:

WHERE cannot directly filter window functions,
so we use a subquery.

6️⃣ FINAL SELECT
SELECT emp_id, name, department, salary

Only required columns are returned

rnk is not shown

✅ Final Output
emp_id	name	department	salary
1	A	IT	90000
2	B	IT	85000
3	C	IT	85000
4	D	IT	70000
5	E	HR	80000
6	F	HR	75000
7	G	HR	72000


🔹 Why DENSE_RANK()?

Handles duplicate salaries
Ensures exactly top 3 salary levels

26. What is index?

An index is a data structure that helps the database find rows faster, just like an index in a book helps you quickly find a topic without reading every page.

Simple Definition (Interview-ready)
An index is a database object that improves query performance by allowing faster data retrieval at the cost of additional storage and slower write operations.

Without Index (Full Table Scan)
SELECT * FROM Employee WHERE emp_id = 101;

Database scans every row in the table
Slow for large tables ❌

With Index
CREATE INDEX idx_emp_id ON Employee(emp_id);

Database directly jumps to the row
Very fast lookup ✅

📚 Types of Indexes in SQL
1️⃣ Clustered Index

👉 Definition:

Determines the physical order of data in a table
Table data is stored in sorted order

👉 Key Points:

Only ONE clustered index per table
Usually created on Primary Key

👉 Example:

CREATE CLUSTERED INDEX idx_emp_id
ON Employee(emp_id);

👉 Example Explanation:

If clustered index is on emp_id
Data will be physically stored like:
1, 2, 3, 4, 5...

2️⃣ Non-Clustered Index

👉 Definition:

Separate structure from table
Stores pointer/reference to actual data

👉 Key Points:

Can have multiple non-clustered indexes
Does NOT change physical order

👉 Example:

CREATE NONCLUSTERED INDEX idx_name
ON Employee(name);

👉 How it works:

Index: name → pointer → actual row
3️⃣ Unique Index

👉 Definition:

Ensures all values in a column are unique

👉 Key Points:

Prevents duplicate values
Automatically created for UNIQUE constraint

👉 Example:

CREATE UNIQUE INDEX idx_email
ON Employee(email);
4️⃣ Composite Index (Multi-column Index)

👉 Definition:

Index on multiple columns

👉 Example:

CREATE INDEX idx_name_dept
ON Employee(name, department);

👉 Important:

Works best when queries use leftmost column

✔ Good:

WHERE name = 'John'

❌ Not optimal:

WHERE department = 'IT'
5️⃣ Full-Text Index

👉 Definition:

Used for searching text data

👉 Example:

CREATE FULLTEXT INDEX idx_desc
ON Employee(description);

👉 Use case:

SELECT * FROM Employee
WHERE MATCH(description) AGAINST('developer');

6️⃣ Bitmap Index (Mostly in Data Warehouses)

👉 Definition:

Uses bitmaps (0s and 1s) for indexing

👉 Best for:

Columns with low cardinality
Gender (M/F)
Status (Active/Inactive)


27. When NOT to use index?

Indexes are powerful, but using them everywhere is a mistake. Here are the clear situations where you should NOT use an index 👇
1️⃣ Small Tables
If a table has very few rows, a full table scan is faster than index lookup.

2️⃣ Columns with Low Cardinality

Low cardinality = few unique values
Examples:
gender (M/F)
status (Active/Inactive)
is_deleted (0/1)

📌 Indexing these columns usually does not help.
WHERE gender = 'M'

3️⃣ Frequently Updated Columns

Indexes slow down:
INSERT
UPDATE
DELETE

❌ Avoid indexing columns that change often.
Example:
last_login_time
status
updated_at

7️⃣ Over-Indexing (Too Many Indexes)
More indexes = more problems:
Slower writes
More storage
Complex optimizer choices
📌 Only index what is needed.

Query optimization is the technique of writing or executing SQL queries in a way that reduces execution time and resource usage by choosing the most efficient execution plan.

Common Query Optimization Techniques

29. What is transaction?

A transaction is a group of SQL operations executed as a single logical unit that ensures data integrity through ACID properties
Real-Life Example (Bank Transfer 💳)

Transfer ₹1000 from Account A → Account B

1. Deduct ₹1000 from Account A
2. Add ₹1000 to Account B

✔ Both must succeed
❌ If one fails → rollback

Transaction Commands
BEGIN TRANSACTION;   -- Start
COMMIT;              -- Save changes
ROLLBACK;            -- Undo changes
SAVEPOINT sp1;       -- Partial rollback

Example Transaction:

BEGIN TRANSACTION;
UPDATE Accounts
SET balance = balance - 1000
WHERE account_id = 1;

UPDATE Accounts
SET balance = balance + 1000
WHERE account_id = 2;

COMMIT;

❌ If error occurs:
ROLLBACK;

Why Transactions Are Important

Prevent partial updates
Maintain data consistency
Handle failures safely
Support concurrent users

🧠 ACID Properties in SQL (with Simple Examples)

ACID properties ensure that database transactions are reliable and safe.

👉 ACID stands for:

A → Atomicity
C → Consistency
I → Isolation
D → Durability
1️⃣ Atomicity (All or Nothing)

👉 Definition:
A transaction must either complete fully or not happen at all.

💡 Example
BEGIN TRANSACTION;

UPDATE Accounts SET balance = balance - 1000 WHERE id = 1;
UPDATE Accounts SET balance = balance + 1000 WHERE id = 2;

COMMIT;

👉 Scenario:

₹1000 is transferred from Account 1 → Account 2

✔ If both queries succeed → COMMIT
❌ If one fails → ROLLBACK (nothing happens)

🔥 Real Meaning:
“Partial updates are NOT allowed.”

2️⃣ Consistency (Valid State)

👉 Definition:
After a transaction, the database must remain in a valid state (respecting rules, constraints).

💡 Example
UPDATE Accounts SET balance = balance - 5000 WHERE id = 1;

👉 If balance becomes negative (not allowed by constraint):

❌ Transaction fails
✔ Database remains consistent

🔥 Real Meaning:
“Database rules (constraints, triggers) must always be satisfied.”

3️⃣ Isolation (No Interference)

👉 Definition:
Multiple transactions should not interfere with each other.

💡 Example
Transaction 1:
UPDATE Accounts SET balance = balance - 1000 WHERE id = 1;
Transaction 2 (at same time):
SELECT balance FROM Accounts WHERE id = 1;

👉 Without isolation:
Transaction 2 might read wrong/temporary value

👉 With isolation:
✔ Each transaction works independently

🔥 Real Meaning:

“Transactions behave as if they are executed one by one.”

4️⃣ Durability (Permanent Changes)

👉 Definition:
Once a transaction is committed, changes are permanently saved, even if system crashes.

💡 Example
COMMIT;

👉 After commit:

Data is stored on disk
Even if server crashes → data remains
🔥 Real Meaning:

“Committed data is never lost.”

30. Difference between COMMIT and ROLLBACK and savepoint.

Imagine This Scenario 🏦
You are doing a bank transaction:
Deduct money from Account A
Add money to Account B
Log the transaction

1️⃣ COMMIT – “Make changes permanent”
Meaning
COMMIT saves all changes permanently to the database.

Example
BEGIN TRANSACTION;

UPDATE Accounts
SET balance = balance - 500
WHERE account_id = 1;

UPDATE Accounts
SET balance = balance + 500
WHERE account_id = 2;

COMMIT;

✔ Money transferred
✔ Changes saved
✔ Cannot undo after commit

2️⃣ ROLLBACK – “Undo changes”
Meaning
ROLLBACK undoes all changes made in the current transaction.

Example
BEGIN TRANSACTION;

UPDATE Accounts
SET balance = balance - 500
WHERE account_id = 1;

-- Something went wrong
ROLLBACK;

❌ Deduction undone
❌ Database returns to original state

3️⃣ SAVEPOINT – “Checkpoint inside a transaction”
Meaning
A SAVEPOINT allows you to rollback to a specific point, not the entire transaction.

🔁 SAVEPOINT + ROLLBACK Example
BEGIN TRANSACTION;

-- Step 1
UPDATE Accounts
SET balance = balance - 500
WHERE account_id = 1;

SAVEPOINT sp1;

-- Step 2
UPDATE Accounts
SET balance = balance + 500
WHERE account_id = 2;

SAVEPOINT sp2;

-- Step 3 (fails)
INSERT INTO TransactionLog VALUES (...);

-- Rollback only step 3
ROLLBACK TO sp2;

COMMIT;

What Happens?
Step	Result
Deduct from A	✅ Kept
Add to B	✅ Kept
Log transaction	❌ Undone
Final commit	✅ Saved

Difference Summary Table
Command	What it does
BEGIN	Starts transaction
COMMIT	Saves all changes
ROLLBACK	Undo entire transaction
SAVEPOINT	Mark a point to rollback to
ROLLBACK TO SAVEPOINT	Undo part of transaction
Important Interview Points ⚠️

COMMIT ends transaction
ROLLBACK ends transaction
SAVEPOINT does not end transaction
You can have multiple savepoints
After COMMIT, rollback is impossible

One-Line Interview Answer 🎯
SAVEPOINT creates a checkpoint inside a transaction, ROLLBACK undoes changes, and COMMIT permanently saves all changes to the database.

31. How to fetch even rows from a table?

✅ Recommended Method (Using ROW_NUMBER())
SELECT *
FROM (
    SELECT *,
           ROW_NUMBER() OVER (ORDER BY emp_id) AS rn
    FROM Employee
) t
WHERE rn % 2 = 0;

🔍 How It Works (Execution Explanation)

ROW_NUMBER() assigns a unique sequence number to each row
ORDER BY emp_id ensures consistent row numbering
rn % 2 = 0 filters even-numbered rows

32. Find employees who didn’t receive salary this month

2	2026-01	2026-01-06

👉 Employees C and D did NOT receive salary this month.

SELECT e.emp_id, e.name
FROM Employee e
LEFT JOIN Salary s
    ON e.emp_id = s.emp_id
    AND s.salary_month = '2026-01'

LEFT JOIN keeps all employees
Salary rows are matched only for current month
Employees with no matching salary record get NULL
WHERE s.emp_id IS NULL filters unpaid employees

34. What happens if we use GROUP BY without aggregate function?
Short answer: It is valid SQL, but its behavior depends on what you select.

Let’s break it down clearly 👇

Case 1️⃣ GROUP BY with the same columns in SELECT (Valid & Meaningful)
SELECT department
FROM Employee
GROUP BY department;

What happens?
Rows are grouped by department
One row per department is returned
Acts like DISTINCT

Output
department
IT
HR
Finance

📌 Equivalent to:

SELECT DISTINCT department FROM Employee;

Case 2️⃣ GROUP BY with multiple columns, no aggregates (Valid)
SELECT department, job_role
FROM Employee
GROUP BY department, job_role;

What happens?
Returns unique combinations
No calculations, just grouping

Case 3️⃣ GROUP BY but selecting a column not in GROUP BY ❌
SELECT department, name
FROM Employee
GROUP BY department;

Using GROUP BY without aggregate functions is valid only when all selected columns are included in the GROUP BY, in which case it behaves like DISTINCT; otherwise it results in an error or unpredictable output.

35. Can we use WHERE with aggregate function? Why not?

Short answer: ❌ No, we cannot use aggregate functions in the WHERE clause.

Why NOT? (Core Reason)

👉 Because of SQL execution order.

Logical Execution Order (simplified)
FROM
WHERE        ← runs BEFORE aggregation
GROUP BY
HAVING       ← runs AFTER aggregation
SELECT

📌 Since WHERE runs before GROUP BY,
aggregates don’t exist yet when WHERE is evaluated.

Example to Understand Clearly
❌ Invalid Query
SELECT department, COUNT(*) 
FROM Employee
WHERE COUNT(*) > 2
GROUP BY department;

❌ Error:
Invalid use of group function

Why?
COUNT(*) is calculated after GROUP BY
WHERE tries to filter before counting

✅ Correct Way: Use HAVING
SELECT department, COUNT(*) 
FROM Employee
GROUP BY department
HAVING COUNT(*) > 2;

Meaning
👉 “Show only departments having more than 2 employees”

Can WHERE and HAVING Be Used Together?
✔ Yes

SELECT department, COUNT(*) 
FROM Employee
WHERE salary > 40000       -- row-level filter
GROUP BY department
HAVING COUNT(*) > 2;       -- group-level filter

Interview One-Liner 🎯
Aggregate functions cannot be used in WHERE because WHERE is evaluated before GROUP BY; HAVING is used instead to filter aggregated results.

37. What is VIEW?

A VIEW is a virtual table that represents the result of a stored SELECT query and provides abstraction, security, and simplicity without storing data.

Basic Syntax
CREATE VIEW emp_view AS
SELECT emp_id, name, department, salary
FROM Employee;

How VIEW Works (Internally)
View stores only the SQL query

When you query the view:
SELECT * FROM emp_view;

Example
Base Table: Employee
emp_id	name	department	salary
1	A	IT	50000
2	B	HR	40000
View Creation
CREATE VIEW it_employees AS
SELECT emp_id, name, salary
FROM Employee
WHERE department = 'IT';

Query the View
SELECT * FROM it_employees;

Output
emp_id	name	salary
1	A	50000
