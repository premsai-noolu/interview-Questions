🔹 Basic HTML (Must-Know)

1. What is HTML? Is it a programming language?
HTML (HyperText Markup Language) is the standard markup language used to create and structure web pages. It defines the structure and content of a webpage using elements like headings, paragraphs, images, links, forms, etc.

Example:
<h1>Welcome</h1>
<p>This is a paragraph</p>

❓ Is HTML a programming language?
No, HTML is NOT a programming language.

🔹 Why?
A programming language can:
Perform logic (if/else)
Use loops
Manipulate data

HTML cannot do any of these.

🔹 HTML:
Describes what content is (structure)
Does not describe how to process data
Has no conditions, loops, or functions
That’s why it’s called a markup language, not a programming language.

2. What are HTML elements and attributes

🔹 HTML Elements
An HTML element is a building block of a web page.
It usually consists of:

Opening tag
Content
Closing tag

Example:
<p>Hello World</p>

Here:
<p> → opening tag
Hello World → content
</p> → closing tag

📌 Some elements are self-closing (void elements) and don’t have closing tags:
<img src="image.jpg" alt="sample image" />
<br />
<input />

🔹 HTML Attributes
Attributes provide additional information about an element.
They are written inside the opening tag as name="value" pairs.

Example:
<img src="logo.png" alt="Company Logo" width="200" />

Here:

src, alt, width → attributes
They modify or describe the behavior or appearance of the element

🔹 Key Points (Interview Important)
Attributes always appear in the opening tag
Attributes usually come in name–value pairs
Some attributes are global attributes (can be used on any element)

Common Global Attributes:

id
class
style
title

3.What are void (self-closing) elements?

Void elements are HTML elements that do not have closing tags and cannot contain any content. They are used to insert standalone elements such as images, line breaks, and form inputs. Examples include img, br, input, and hr.

4. Difference between <div> and <span>.

Both <div> and <span> are non-semantic HTML elements, but they differ mainly in display behavior and usage.

🔹 Key Differences (Interview-Friendly Table)
Feature	                <div>	                  <span>
Type	          Block-level element	    Inline element
New line	    Starts on a new line	    Does not start on a new line
Width	Takes full available width	        Takes only content width
Usage	Used for layout / grouping blocks	Used for styling inline text
Can contain	Block + inline elements	        Inline elements only
Common use	Sections, containers, layout	Highlighting text, icons

🔹 Example
<div style="border:1px solid black">
  This is a div
</div>

<span style="border:1px solid red">
  This is a span
</span>

Browser Output:

div appears on a new line and spans full width
span stays inline with text

🔹 Display Property (Important)
By default:

div {
  display: block;
}
span {
  display: inline;
}

👉 You can change behavior using CSS:

span {
  display: block;
}

🔹 Interview-Ready Answer (Best)
<div> is a block-level element used to group and structure sections of a webpage, while <span> is an inline element used to style or group small portions of text within a line. A div starts on a new line and takes full width, whereas a span does not.

7. What is DOCTYPE and why is it required?

DOCTYPE (Document Type Declaration) tells the browser which version of HTML the page is written in and how the browser should render the page.

It must be written at the very top of the HTML document, before the <html> tag.

Example (HTML5):
<!DOCTYPE html>

🔹 Why is DOCTYPE Required?
1️⃣ Tells the Browser How to Render the Page
With DOCTYPE → Standards Mode
Without DOCTYPE → Quirks Mode

👉 Standards Mode follows modern web standards
👉 Quirks Mode behaves like old browsers (can break layouts)

2️⃣ Prevents Layout & CSS Issues

Without DOCTYPE:
CSS behaves inconsistently
Box model issues
Unexpected spacing & alignment problems

With DOCTYPE:
Consistent rendering across browsers

8. What are block-level and inline elements?

Block-level elements start on a new line and take up the full width of their container, making them suitable for layout and structure. Inline elements do not start on a new line and take only the space required by their content, making them suitable for text-level styling.

Examples (Block-level):
<div></div>
<p></p>
<h1></h1>
<section></section>
<article></article>
<header></header>
<footer></footer>
<ul></ul>
<li></li>

Examples (inline):
<span></span>
<a></a>
<strong></strong>
<em></em>
<img>
<label>

9. What is the difference between id and class?

An id uniquely identifies a single HTML element and must be used only once on a page, while a class can be applied to multiple elements to group them for styling or behavior. IDs have higher CSS specificity than classes.
🔹 Example

<p class="text">Paragraph 1</p>
<p class="text">Paragraph 2</p>

#mainTitle {
  color: blue;
}

.text {
  color: green;
}

🔹 Important Interview Points
❌ IDs should not be repeated
✅ One element can have multiple classes
<div class="card active highlight"></div>

❌ One element should not have multiple IDs

🔹 JavaScript Usage Example
document.getElementById("mainTitle");
document.querySelectorAll(".text");

11. Difference between href and src.

href is used to reference and link external resources, while src is used to embed external resources directly into the webpage.
🔹 href (Hypertext Reference)

Used to link one resource to another
The resource is not embedded, only referenced

Commonly used in <a> and <link>

<a href="https://example.com">Visit</a>
<link rel="stylesheet" href="style.css">

👉 Clicking or loading the link navigates to or applies the resource.

🔹 src (Source)

Used to embed a resource into the page
The resource becomes part of the page content
Used in <img>, <script>, <iframe>, <audio>, <video>

<img src="logo.png">
<script src="app.js"></script>

👉 Browser fetches and displays/executes the resource.

24. Difference between localStorage, sessionStorage, and cookies.
localStorage stores data permanently until cleared, sessionStorage stores data for a single session or tab, and cookies store small amounts of data that are sent to the server with every request and can have an expiry time.

🔹 localStorage
✔ Features

Data persists even after browser restart
Shared across all tabs of the same domain

Example
localStorage.setItem("theme", "dark");
localStorage.getItem("theme");

👉 Use for:
Theme settings
Language preferences
Non-sensitive data

🔹 sessionStorage
✔ Features

Data exists only for the current tab/session
Cleared when tab is closed

Example
sessionStorage.setItem("step", "2");
sessionStorage.getItem("step");

👉 Use for:
Multi-step forms
Temporary state

🔹 Cookies
✔ Features

Sent with every HTTP request
Small storage size
Can be secured (HttpOnly, Secure)

Example
document.cookie = "user=Prem; expires=Fri, 31 Jan 2026 12:00:00 UTC;";

👉 Use for:
Authentication
Session management
Tracking

27. What is the difference between GET and POST methods?
28. What happens when you submit a form?

🔹 GET Method

Used to request / fetch data from the server
Data is sent in the URL (query string)
Not secure (data visible in URL)
Can be cached and bookmarked
Limited data length

Example:
GET /search?product=mobile&page=1 HTTP/1.1

<form method="GET" action="/search">
  <input type="text" name="product">
  <button type="submit">Search</button>
</form>

📌 URL after submit:
/search?product=mobile

🔹 POST Method

Used to send data to the server
Data is sent in the request body
More secure than GET (not visible in URL)
Cannot be bookmarked
No data size limitation (practical)

Example:
<form method="POST" action="/login">
  <input type="email" name="email">
  <input type="password" name="password">
  <button type="submit">Login</button>
</form>

📌 Data sent in body:
email=user@gmail.com
password=123456

🔍 GET vs POST (Quick Comparison Table)
Feature	         GET	     POST
Purpose	     Fetch data	     Send data
Data location	URL	         Request body
Security	Less secure	     More secure
Cacheable	Yes	             No
Bookmark	Yes	             No
Data size	Limited	         Large
Use case	Search, filters	 Login, signup

⭐ Interview One-Liners
GET: Used to retrieve data from the server.
POST: Used to send data securely to the server.

2️⃣ What happens when you submit a form?

When a form is submitted, the following steps occur:
🔹 Step-by-Step Flow

1️⃣ User clicks Submit button
2️⃣ Browser collects form data (name/value pairs)
3️⃣ Browser checks HTML validations (required, pattern, etc.)
4️⃣ Browser creates an HTTP request
5️⃣ Request is sent to the server using GET or POST
6️⃣ Server processes the request
7️⃣ Server sends back a response
8️⃣ Browser renders the response

🔹 Example Flow (POST Login Form)
<form method="POST" action="/login">
  <input name="email">
  <input name="password">
  <button type="submit">Login</button>
</form>


📌 Browser sends:

POST /login HTTP/1.1
Content-Type: application/x-www-form-urlencoded

email=test@gmail.com&password=1234


📌 Server responds:
Success → Redirect to dashboard
Failure → Show error message

Q: Where is form data sent in GET?
👉 URL
Q: Where is form data sent in POST?
👉 Request body

🎯 Final Interview Summary (Perfect Answer)

GET is used to retrieve data and sends data via URL, while POST is used to send data securely in the request body.
When a form is submitted, the browser validates inputs, creates an HTTP request, sends it to the server, and displays the server’s response.

36. Client-side validation vs server-side validation.

Client-side validation happens in the browser, before data is sent to the server.

🔹 How it’s done
HTML5 attributes (required, pattern, min, max)
JavaScript (custom validation)

🔹 Example
<input type="password" minlength="8" required>

📌 Error shown instantly in the browser.

✅ Advantages

Fast feedback
Better user experience
Reduces server load

3️⃣ Server-Side Validation

Server-side validation happens on the server after the form is submitted.

🔹 Example (Node.js / Express)
app.post("/register", (req, res) => {
  if (!req.body.email) {
    return res.status(400).send("Email is required");
  }
});

✅ Advantages

Secure and reliable
Cannot be bypassed
Protects database and backend

Client-side validation:
Validation done in the browser before sending data to the server.

Server-side validation:
Validation done on the server after receiving data.

🎯 Final Interview Answer (Perfect)
Form validation ensures that user inputs are correct and complete. Client-side validation improves user experience by giving instant feedback, while server-side validation is essential for security and data integrity. Both should be used together.

37. How do you prevent form submission?

Form submission can be prevented by stopping the default browser behavior.
🔹 Common Ways
✅ 1. Using JavaScript event.preventDefault()

This is the most common and correct way.

Example:
<form id="myForm">
  <input type="text" required>
  <button type="submit">Submit</button>
</form>

<script>
  document.getElementById("myForm").addEventListener("submit", function (event) {
    event.preventDefault(); // stops form submission
    alert("Form submission prevented");
  });
</script>

📌 Prevents page reload and form submission.

✅ 2. Return false in onsubmit
Example:
<form onsubmit="return false;">
  <input type="text">
  <button type="submit">Submit</button>
</form>

📌 If false is returned, the form is not submitted.

⚠️ Not recommended for modern applications (inline JS).

✅ 3. Button type = button (Not submit)
<button type="button">Click Me</button>

📌 Form won’t submit because only type="submit" triggers submission.

✅ 4. Using HTML5 Validation (required, pattern)
<input type="email" required>

📌 Browser prevents submission if validation fails.
⚠️ This is validation-based prevention, not programmatic control.

42. What is viewport?

The viewport is the visible area of a web page on a device screen.
👉 It changes based on the device:
Desktop → large viewport
Mobile → small viewport

🔹 Why viewport is important
Controls how content scales
Helps make websites responsive
Essential for mobile-friendly design

🔹 Meta Viewport Example
<meta name="viewport" content="width=device-width, initial-scale=1.0">

📌 Meaning:
width=device-width → page width = device screen width
initial-scale=1.0 → no zoom on load

⭐ Interview One-Liner
The viewport is the visible area of a webpage, and it controls how content is displayed on different screen sizes.

50. How do you make an iframe secure?

Since iframes load external content, they can be a security risk. Security is improved using these methods:

🔹 1. sandbox attribute (MOST IMPORTANT)
<iframe src="https://example.com" sandbox></iframe>

📌 Restricts:
Scripts
Forms
Popups
Navigation

🔹 Allow specific features only
<iframe
  src="https://example.com"
  sandbox="allow-scripts allow-same-origin">
</iframe>

🔹 2. allow attribute (Permissions policy)
<iframe
  src="https://example.com"
  allow="fullscreen; autoplay">
</iframe>

🔹 3. Use HTTPS
<iframe src="https://secure-site.com"></iframe>

🔹 4. Restrict referrer info
<iframe src="https://example.com" referrerpolicy="no-referrer"></iframe>

🔹 5. Content Security Policy (CSP)
Restrict which domains can be embedded.

51. What is sandbox attribute in iframe?

The sandbox attribute is used to restrict what an iframe is allowed to do, making it more secure.
👉 By default, sandbox applies strict security restrictions to the embedded page.

🔹 What does sandbox restrict?
When sandbox is used without values, it blocks:

JavaScript execution
Form submission
Pop-ups
Access to parent page
Top-level navigation

🔹 Basic Example
<iframe src="https://example.com" sandbox></iframe>

📌 Embedded content runs in a restricted environment.

🔹 Allow specific permissions
<iframe
  src="https://example.com"
  sandbox="allow-scripts allow-forms">
</iframe>

📌 Only scripts and forms are allowed.

⭐ Interview One-Liner
The sandbox attribute secures an iframe by restricting its capabilities unless explicitly allowed.


52. What is responsive image?

A responsive image automatically adapts to different screen sizes and resolutions, so the browser loads the most appropriate image for the user’s device.

👉 Goal:

Faster loading
Better performance
Optimized for mobile, tablet, desktop

🔹 Why responsive images are needed
Mobile screens don’t need large desktop images
Large images slow down websites
Saves bandwidth and improves Core Web Vitals

🔹 Example (Responsive Image)
<img 
  src="small.jpg"
  srcset="small.jpg 480w, medium.jpg 768w, large.jpg 1200w"
  sizes="(max-width: 600px) 480px, 1200px"
  alt="Product image">

📌 Browser chooses the best image based on screen size.

⭐ Interview One-Liner
Responsive images adapt to different screen sizes to improve performance and user experience.

53. What is srcset?

srcset is an HTML attribute that provides multiple image sources so the browser can choose the best one based on:

Screen width
Device pixel ratio (DPR)

🔹 Example
<img 
  src="image.jpg"
  srcset="image-1x.jpg 1x, image-2x.jpg 2x"
  alt="Profile picture">

📌 On high-resolution screens (Retina), browser loads 2x image.

⭐ Interview One-Liner
srcset allows the browser to select the most suitable image from multiple options.
