🔹 Express.js Interview Questions (For MERN Stack Developer)
🔸 Basics

1. What is Express.js?

Express.js is a fast, minimal, and flexible web application framework built on top of Node.js.
It is mainly used to build RESTful APIs and server-side web applications.

In simple terms:
Node.js provides the runtime, and Express.js provides the structure and tools to build web applications easily.

🔹 Key Features of Express.js

🚀 Fast & lightweight
🛣️ Easy routing
🧩 Middleware support
🔐 Security integrations
🔄 Request–response handling
📦 Works well with MongoDB (MERN stack)

🔹 Example (Simple Express Server)
const express = require("express");
const app = express();

app.get("/", (req, res) => {
  res.send("Hello from Express");
});

app.listen(3000, () => {
  console.log("Server running on port 3000");
});

Express acts as the bridge between frontend (React) and database (MongoDB).

🔹 One-line Interview Answer (Very Important ⭐)
Express.js is a minimal Node.js framework used to build fast, scalable backend applications and REST APIs by simplifying routing, middleware, and request–response handling.

2. Why do we use Express.js instead of Node.js alone?

Node.js alone provides a low-level way to handle HTTP requests, but building real-world applications with it becomes complex and repetitive.
Express.js is used to simplify and speed up backend development.

🔹 Using Node.js without Express (Pain Points)

Manual routing
Repetitive code
No middleware system
Harder error handling
Poor scalability for large apps

Example (pure Node.js):

const http = require("http");
http.createServer((req, res) => {
  if (req.url === "/users" && req.method === "GET") {
    res.end("Users list");
  }
}).listen(3000);

🔹 Using Express.js (Clean & Scalable)
const express = require("express");
const app = express();

app.get("/users", (req, res) => {
  res.send("Users list");
});

app.listen(3000);

We use Express.js because it provides a simple, structured, and scalable way to build web servers and REST APIs on top of Node.js by handling routing, middleware, and errors efficiently.

3. What is middleware in Express?

Middleware in Express is a function that runs between the request and the response.
It has access to request (req), response (res), and the next (next) function.

👉 Middleware is used to modify requests, execute logic, or control the flow before the final response is sent.

🔹 Middleware Function Signature
(req, res, next) => { }

req → incoming request

res → outgoing response

next() → passes control to the next middleware

🔹 Request–Response Flow (Very Important)
Client → Middleware → Middleware → Route Handler → Response

🔹 Simple Example
app.use((req, res, next) => {
  console.log("Request received");
  next();
});

✔ If next() is not called, the request will hang.

🔹 Why Middleware is Used

Authentication & authorization
Logging
Validation
Error handling
Parsing request body
Security

🔹 Real-World Example (Auth Middleware)
const authMiddleware = (req, res, next) => {
  if (!req.headers.authorization) {
    return res.status(401).json({ message: "Unauthorized" });
  }
  next();
};

app.get("/profile", authMiddleware, (req, res) => {
  res.send("User Profile");
});

🔹 Built-in Middleware Example
app.use(express.json());

🔹 One-line Interview Answer ⭐
Middleware in Express is a function that executes during the request–response cycle to process, modify, or validate requests before sending a response.

4. What are the different types of middleware in Express?

There are 5 main types of middleware, and this question is very common in interviews.

🔹 1️⃣ Application-Level Middleware

Applied to the entire application using app.use() or app.METHOD().

Example
app.use((req, res, next) => {
  console.log("Application-level middleware");
  next();
});

✔ Runs for every request.

🔹 2️⃣ Router-Level Middleware

Applied only to specific routes using express.Router().

Example
const router = express.Router();

router.use((req, res, next) => {
  console.log("Router-level middleware");
  next();
});

router.get("/users", (req, res) => {
  res.send("Users");
});

✔ Helps in modular route design.

🔹 3️⃣ Built-in Middleware

Provided directly by Express.

Common Examples
app.use(express.json());
app.use(express.urlencoded({ extended: true }));
app.use(express.static("public"));

✔ Used for parsing data and serving static files.

🔹 4️⃣ Third-Party Middleware

External packages installed via npm.

Examples

cors
helmet
morgan
multer
express-rate-limit

const cors = require("cors");
app.use(cors());

✔ Used for security, logging, uploads, performance.

🔹 5️⃣ Error-Handling Middleware ⭐ (Very Important)

Used to handle errors centrally.

Signature (4 parameters)
(err, req, res, next) => { }

Example
app.use((err, req, res, next) => {
  res.status(500).json({ error: err.message });
});

✔ Must be defined after routes.

5. What is app.use()?

app.use() is used to register middleware in an Express application.
It tells Express to execute a function for every incoming request (or for a specific path).

🔹 Basic Syntax
app.use([path], middlewareFunction);

path → optional (default is /)

middlewareFunction → function with req, res, next

🔹 Example 1: Global Middleware
app.use((req, res, next) => {
  console.log("Request received");
  next();
});

✔ Runs for all routes and HTTP methods.

🔹 Example 2: Built-in Middleware
app.use(express.json());

✔ Parses JSON request bodies.

🔹 Example 3: Path-Specific Middleware
app.use("/admin", (req, res, next) => {
  console.log("Admin route accessed");
  next();
});

✔ Runs only for /admin routes.

🔹 Example 4: Using Router with app.use()
const userRoutes = require("./routes/userRoutes");
app.use("/users", userRoutes);

✔ Helps keep code clean and modular.

🔹 Important Behavior (Interview Point ⭐)
Works for all HTTP methods (GET, POST, PUT, etc.)
Executes middleware in the order it is defined
Can end the request–response cycle or pass control using next()

6. What is the difference between app.use() and app.get()?

🔹 app.use()

Used to register middleware
Executes for all HTTP methods
Path is optional
Commonly used for middlewares, routers, and global logic

Example
app.use("/users", (req, res, next) => {
  console.log("Middleware for users");
  next();
});

✔ Runs for:

GET /users
POST /users
PUT /users/1
DELETE /users/1

🔹 app.get()

Used to handle GET requests only
Path is mandatory
Mainly used for route handling
Does not act like middleware by default

Example
app.get("/users", (req, res) => {
  res.send("Users list");
});

✔ Runs only for:
GET /users

🔹 Important Interview Trick ⭐
app.use() matches all paths that start with the given path.

app.use("/api", middleware);

✔ Runs for:

/api/users
/api/products

🔸 Routing & Request Handling

7. What is routing in Express?

Routing in Express is the mechanism that determines how an application responds to a client request based on:

URL (path)
HTTP method (GET, POST, PUT, DELETE, etc.)

In simple words:

Routing maps incoming requests → specific code (handlers).

🔹 Basic Routing Syntax
app.METHOD(PATH, HANDLER)

Example
app.get("/users", (req, res) => {
  res.send("Users list");
});

✔ When a client sends GET /users, this handler executes.

🔹 Routing with Multiple HTTP Methods
app.post("/users", (req, res) => {
  res.send("User created");
});

app.put("/users/:id", (req, res) => {
  res.send("User updated");
});

🔹 Route Parameters
app.get("/users/:id", (req, res) => {
  res.send(`User ID: ${req.params.id}`);
});

✔ Dynamic values handled using :.

🔹 Why Routing is Important

Organizes application logic
Supports REST API design
Separates concerns
Makes application scalable

🔹 Using express.Router() (Real-World)
const router = express.Router();

router.get("/", getUsers);
router.post("/", createUser);

app.use("/users", router);

✔ Helps build modular and maintainable apps.

8. What is express.Router() and why is it used?

express.Router() is a mini Express application that is used to create modular, reusable route handlers.
It helps in splitting routes into separate files, making large applications clean, scalable, and maintainable.

🔹 Why do we need express.Router()?

Without Router:
All routes go into app.js
File becomes large and hard to maintain
Poor scalability

With Router:
Routes are grouped by feature (users, auth, products)
Better project structure
Easier testing and debugging

🔹 Basic Example
file(routes/userRoutes.js)
const express = require("express");
const router = express.Router();

router.get("/", (req, res) => {
  res.send("All users");
});

router.post("/", (req, res) => {
  res.send("Create user");
});

module.exports = router;

app.js
const userRoutes = require("./routes/userRoutes");
app.use("/users", userRoutes);

✔ Final routes:

GET /users

POST /users

🔹 Router-Level Middleware Example
router.use((req, res, next) => {
  console.log("User route middleware");
  next();
});

✔ Executes only for routes inside this router.

🔹 One-Line Interview Answer ⭐
express.Router() is used to create modular route handlers that help organize and scale Express applications by grouping related routes together.

9. How do you access request data in Express?

In Express, request data is available through the req (request) object.
Depending on where the data comes from, we access it in different ways.

🔹 Main Ways to Access Request Data
1️⃣ req.params – Route Parameters

Used for dynamic values in the URL path.

app.get("/users/:id", (req, res) => {
  console.log(req.params.id);
});

✔ URL: /users/5
✔ Output: 5

2️⃣ req.query – Query String Parameters

Used for optional data in the URL.

app.get("/users", (req, res) => {
  console.log(req.query.page);
});

✔ URL: /users?page=2
✔ Output: 2

3️⃣ req.body – Request Body (POST / PUT)

Used for data sent from client in the request body.

app.use(express.json());

app.post("/users", (req, res) => {
  console.log(req.body);
});

✔ Used with POST, PUT, PATCH

4️⃣ req.headers – Request Headers

Used for auth tokens, content type, cookies.
console.log(req.headers.authorization);

5️⃣ req.cookies (with middleware)

Used to read cookies (requires cookie-parser).
console.log(req.cookies.token);

🔹 One-Line Interview Answer ⭐
In Express, request data is accessed using req.params for route params, req.query for query strings, req.body for request payloads, and req.headers for headers.

10. Explain the request–response cycle in Express.

The request–response cycle in Express describes how a client request is processed and how a response is sent back by the server.

🔹 High-Level Flow (Interview Ready)
Client → Middleware → Route → Response

🔹 Step-by-Step Explanation
1️⃣ Client Sends Request
Browser / Postman / Frontend (React)

Request contains:

URL
HTTP method
Headers
Body (optional)

Example:

GET /users

2️⃣ Express Receives Request
Express creates req and res objects

Starts executing middleware in order of definition

3️⃣ Middleware Execution

Built-in middleware
(express.json(), cors)

Custom middleware
(auth, logging, validation)

app.use((req, res, next) => {
  console.log("Middleware executed");
  next();
});

✔ If next() is called → moves forward
❌ If response is sent → cycle ends

4️⃣ Route Matching & Handler Execution

Express matches:

HTTP method
URL path

app.get("/users", (req, res) => {
  res.json({ users: [] });
});

✔ Route handler sends response

5️⃣ Error Handling (If Error Occurs)

If an error is:
Thrown

Passed using next(err)

Then Express skips normal middleware and goes to error-handling middleware.

app.use((err, req, res, next) => {
  res.status(500).json({ message: err.message });
});

6️⃣ Response Sent to Client

res.send()
res.json()
res.status()

Once response is sent, cycle ends.

🔹 Visual Flow (Detailed)
Client
  ↓
app.use() middleware
  ↓
router middleware
  ↓
route handler
  ↓
error middleware (if any)
  ↓
Response

🔹 Important Interview Points ⭐

Middleware executes in order
next() controls flow
Middleware can terminate the cycle
Error middleware has 4 arguments

🔹 One-Line Interview Answer ⭐
In Express, a request flows from the client through middleware functions, then to the matched route handler, optionally through error middleware, and finally sends a response back to the client.

11. What happens if next() is not called in middleware?

If next() is not called in a middleware and no response is sent, the request–response cycle stops, and the client request will hang (no response is returned).

🔹 Why this happens
Express moves to the next middleware or route handler only when next() is called.
If neither next() nor a response (res.send, res.json, etc.) is sent, Express doesn’t know what to do next.

🔹 Example: ❌ Problem Case (Request Hangs)
app.use((req, res, next) => {
  console.log("Middleware executed");
  // next() is missing
});

✔ Console logs
❌ Browser/Postman waits forever

🔹 Example: ✅ Correct Usage
Option 1: Call next()
app.use((req, res, next) => {
  console.log("Middleware executed");
  next();
});

Option 2: Send Response
app.use((req, res, next) => {
  return res.status(401).send("Unauthorized");
});

✔ Request ends here
✔ Route handler will NOT execute

🔹 Special Case: Error Middleware

When an error occurs:
next(err);

Express skips remaining normal middleware and moves to error-handling middleware.

🔹 Important Interview Points ⭐

Either call next() or send a response
Middleware controls the request flow
Missing next() causes request to hang
Error middleware is triggered via next(err)

🔹 One-Line Interview Answer ⭐
If next() is not called and no response is sent, the request will hang because Express cannot move to the next middleware or route handler.

12. What is the difference between res.send() and res.json()?

Both res.send() and res.json() are used to send responses to the client, but they are used in slightly different scenarios.

🔹 res.send()

Can send any type of data
Automatically sets Content-Type based on data
Used for text, HTML, JSON, buffers

Example
res.send("Hello World");
res.send({ name: "Prem" });
res.send("<h1>Hello</h1>");

🔹 res.json()

Specifically used to send JSON responses
Always sets Content-Type: application/json
Automatically converts objects to JSON

Example
res.json({ name: "Prem", role: "MERN Developer" });

When you send an object:

res.send({ a: 1 });
res.json({ a: 1 });

✔ Both behave almost the same, but:

👉 Best practice:

Use res.json() for APIs
Use res.send() for simple messages

🔹 Status Code with Response
res.status(200).json({ success: true });
res.status(404).send("Not Found");

🔹 One-Line Interview Answer ⭐
res.send() can send any type of response, while res.json() is specifically used to send JSON responses with the correct content type, making it ideal for REST APIs.

🔸 Error Handling

13. How do you handle errors in Express?

Errors in Express are handled using error-handling middleware, which allows you to catch, process, and respond to errors centrally instead of handling them in every route.

🔹 1️⃣ Basic Error Handling Concept

When an error occurs:
You either throw an error
Or pass it using next(err)

Express then forwards the error to error-handling middleware.

🔹 2️⃣ Error-Handling Middleware (Very Important ⭐)
Syntax (4 parameters – must remember)
(err, req, res, next) => { }

Example
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({
    success: false,
    message: err.message
  });
});

📌 Must be placed after all routes.

🔹 3️⃣ Passing Errors with next(err)
app.get("/user", (req, res, next) => {
  const error = new Error("User not found");
  error.status = 404;
  next(error);
});

✔ Express skips normal middleware
✔ Jumps directly to error middleware

🔹 4️⃣ Handling Errors in Async Routes (Important)

Express does not catch async errors automatically.

❌ Problem:

app.get("/data", async (req, res) => {
  throw new Error("Failed");
});

✅ Solution:

app.get("/data", async (req, res, next) => {
  try {
    throw new Error("Failed");
  } catch (err) {
    next(err);
  }
});

🔹 6️⃣ 404 Error Handling
app.use((req, res, next) => {
  res.status(404).json({ message: "Route not found" });
});

🔹 Important Interview Points ⭐

Error middleware has 4 arguments
It must be last middleware
Use next(err) to forward errors
Centralized error handling improves maintainability

🔹 One-Line Interview Answer ⭐
Errors in Express are handled using centralized error-handling middleware with four parameters, where errors are passed using next(err) and responded with appropriate status codes.

14. What is the purpose of next(err)?

next(err) is used to pass an error to Express’s error-handling middleware.
When next(err) is called, Express stops executing normal middleware and route handlers and directly jumps to the error-handling middleware.

🔹 How next(err) Works (Flow)
Request
  ↓
Middleware / Route
  ↓
next(err)
  ↓
Error-handling middleware
  ↓
Response

🔹 Example: Using next(err)
app.get("/user/:id", (req, res, next) => {
  if (req.params.id !== "1") {
    return next(new Error("User not found"));
  }
  res.send("User found");
});

🔹 Error-Handling Middleware
app.use((err, req, res, next) => {
  res.status(404).json({ message: err.message });
});

✔ Only runs when next(err) is called or an error occurs.

🔹 Important Interview Points ⭐

Skips all remaining normal middleware
Directly invokes error-handling middleware
Helps centralize error handling
Prevents duplicate error responses

🔹 Common Mistake ❌

Calling both response and next(err):

res.send("Error");
next(err); // ❌ causes headers already sent error

🔹 One-Line Interview Answer ⭐
next(err) is used to forward an error to Express’s error-handling middleware, skipping the normal middleware and route execution flow.

15. What happens if an error is thrown inside an async function in Express?

If an error is thrown inside an async route handler, Express does NOT catch it automatically (in older versions / by default).
As a result, the request may crash the app or remain unhandled unless the error is explicitly passed to error-handling middleware.

🔹 Why this happens

Express was originally designed for synchronous code.
Errors thrown inside Promises / async–await are not automatically forwarded to next(err) unless handled properly.

🔹 ❌ Problem Example (Unhandled Async Error)
app.get("/data", async (req, res) => {
  throw new Error("Database failed");
});

✔ Error is thrown
❌ Express does not call error middleware automatically

🔹 ✅ Solution 1: Use try–catch and next(err)
app.get("/data", async (req, res, next) => {
  try {
    throw new Error("Database failed");
  } catch (err) {
    next(err);
  }
});

✔ Error goes to error middleware

🔹 ✅ Solution 2: Async Handler Wrapper (Best Practice ⭐)
const asyncHandler = fn => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

app.get("/data", asyncHandler(async (req, res) => {
  throw new Error("Database failed");
}));

✔ Cleaner
✔ Used in production apps

🔹 Error Middleware
app.use((err, req, res, next) => {
  res.status(500).json({ message: err.message });
});

🔹 Important Interview Points ⭐

Async errors are not caught automatically
Must use try–catch or async wrapper
next(err) forwards error properly
Prevents server crashes

🔹 One-Line Interview Answer ⭐
Errors thrown inside async functions are not automatically caught by Express, so they must be handled using try–catch or passed to error-handling middleware using next(err).

🔸 Middleware & Security

16. What is CORS?

CORS (Cross-Origin Resource Sharing) is a security mechanism implemented by browsers that controls whether a web application running on one origin is allowed to access resources from another origin.

👉 Origin = protocol + domain + port

🔹 What is a Cross-Origin Request?

A request is cross-origin if any of these differ:

Protocol (http vs https)
Domain (localhost vs example.com)
Port (3000 vs 5173)

Example:

Frontend: http://localhost:5173 (React)
Backend : http://localhost:3000 (Express)

✔ This is a cross-origin request

🔹 Why CORS is Needed

Without CORS:

Any website could access your APIs
Security risks (data theft, CSRF)
CORS allows the server to explicitly define who can access it.

🔹 CORS Error Example
Access to fetch at 'http://localhost:3000/api'
from origin 'http://localhost:5173'
has been blocked by CORS policy

🔹 Enabling CORS in Express (Most Common)
const cors = require("cors");

app.use(cors({
  origin: "http://localhost:5173",
  credentials: true
}));

🔹 Common CORS Options
Option	       Purpose
origin	      Allowed frontend
methods	      Allowed HTTP methods
credentials	  Allow cookies/auth
allowedHeaders	Allowed headers
🔹 Preflight Request (Important ⭐)

Browser sends an OPTIONS request.
Checks server permissions before actual request.
Happens for PUT, DELETE, custom headers.

17. What is a Preflight Request?

A preflight request is an automatic OPTIONS request sent by the browser before the actual API request.

👉 The purpose is to ask the server:
“Is it safe for me (this origin) to make this request with these methods and headers?”

🔹 Why Browsers Send Preflight Requests

Browsers enforce CORS security.
If a request is not a simple request, the browser first checks permissions.

The server must explicitly allow:

Origin
HTTP method
Headers
Credentials (cookies)

Only then will the actual request be sent.

🔹 When Does a Preflight Request Happen? ⭐
A preflight request is triggered when ANY of these are true:

1️⃣ HTTP Method is NOT simple

Simple methods:

GET
POST
HEAD

Non-simple (preflight required):

PUT
DELETE
PATCH

2️⃣ Custom Headers are used

Examples:

Authorization
X-Custom-Header
Content-Type: application/json

3️⃣ Credentials are sent

Cookies
Authorization headers
credentials: true

🔹 Step-by-Step Flow (Very Important)
Example Scenario

Frontend (React):
http://localhost:5173

Backend (Express):
http://localhost:3000

Request:

fetch("http://localhost:3000/api/user/1", {
  method: "PUT",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer token"
  },
  credentials: "include"
});

🔄 What Browser Does
🟡 Step 1: Preflight (OPTIONS)
OPTIONS /api/user/1 HTTP/1.1
Origin: http://localhost:5173
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: Content-Type, Authorization

🟢 Step 2: Server Responds
Server must reply with:

Access-Control-Allow-Origin: http://localhost:5173
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Allow-Credentials: true

✔ Browser checks these headers

🟢 Step 3: Actual Request is Sent
PUT /api/user/1

If ❌ not allowed → request is blocked

🔹 How Express Handles Preflight Requests

Using cors package:

app.use(cors({
  origin: "http://localhost:5173",
  credentials: true,
  methods: ["GET", "POST", "PUT", "DELETE"],
  allowedHeaders: ["Content-Type", "Authorization"]
}));

✔ Express automatically handles OPTIONS requests

🔹 What If Server Does NOT Respond Properly?

Browser blocks request
Backend API may still work
Frontend never receives response

👉 This is why CORS errors are frontend-visible but backend looks fine

🔹 Interview-Ready One-Line Answer ⭐
A preflight request is an OPTIONS request sent by the browser to verify CORS permissions before making a non-simple cross-origin request involving custom headers, credentials, or methods like PUT or DELETE.

🔹 Important Interview Points ⭐

CORS is enforced by browser, not server
Backend must allow origin
Needed when frontend & backend are on different origins

🔹 One-Line Interview Answer ⭐
CORS is a browser security feature that restricts cross-origin HTTP requests and allows servers to specify which origins can access their resources.

18. What does credentials: true do in CORS?

credentials: true allows the browser to send credentials (like cookies, authorization headers, or TLS client certificates) along with cross-origin requests.
Without this option, credentials are blocked by the browser for security reasons.

🔹 What are “credentials”?

Credentials include:

🍪 Cookies
🔑 Authorization headers (Bearer token)
🔐 Client-side certificates

🔹 Why credentials: true is needed (Real MERN Example)

Frontend (React)
axios.get("http://localhost:3000/api/profile", {
  withCredentials: true
});

Backend (Express)
app.use(cors({
  origin: "http://localhost:5173",
  credentials: true
}));

✔ Cookies / tokens are sent successfully

🔹 What happens WITHOUT credentials: true?

Browser sends request ❌ without cookies
Auth fails
User appears logged out

🔹 Very Important Rule ⭐ (Interview Favorite)

When credentials: true is enabled:

❌ You CANNOT use
origin: "*"

✅ You MUST specify a single origin
origin: "http://localhost:5173"

Otherwise, browser blocks the request.

🔹 How Browser Enforces This

Server response headers must include:

Access-Control-Allow-Origin: http://localhost:5173
Access-Control-Allow-Credentials: true

If missing → request blocked

🔹 Common Use Cases

JWT stored in HttpOnly cookies
Session-based authentication
Secure login APIs

🔹 One-Line Interview Answer ⭐
credentials: true allows cross-origin requests to include cookies or authorization headers, enabling secure authentication between frontend and backend.

19. What is Helmet and why is it used?

Helmet is a security middleware for Express that helps protect applications from common web vulnerabilities by setting secure HTTP headers.

👉 It does not add features — it reduces security risks.

🔹 Why Helmet is Needed

By default, Express:

Exposes certain HTTP headers

Does not apply security best practices automatically

Helmet helps prevent:

20. What is rate limiting and why is it important?

Rate limiting is a technique used to control the number of requests a client can make to an API within a specific time window.
👉 Its main goal is to protect the server from abuse and overload.

🔹 Why Rate Limiting is Important

Rate limiting helps prevent:

🚨 Brute-force attacks (login APIs)
🤖 Bot abuse
💥 DDoS-like traffic spikes
🔄 Excessive API usage
📉 Server performance degradation

🔹 Real-World Example

Allow 100 requests per IP per 15 minutes
If limit is exceeded → respond with 429 Too Many Requests

🔹 Implementing Rate Limiting in Express

Using express-rate-limit:

const rateLimit = require("express-rate-limit");

const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100,                // max requests per IP
  message: "Too many requests, please try again later"
});

app.use("/api", limiter);

✔ Applied only to /api routes

🔹 How Rate Limiting Works (Internally)

Tracks requests per IP / user
Counts requests in a time window
Blocks requests after limit is reached

🔹 Important Interview Points ⭐
Returns HTTP status 429
Often combined with Redis for distributed systems
Login endpoints need stricter limits

🔹 One-Line Interview Answer ⭐
Rate limiting restricts the number of API requests a client can make in a given time to prevent abuse, improve security, and ensure system stability.

21. How does JWT authentication work in Express?

JWT (JSON Web Token) authentication is a stateless authentication mechanism where the server verifies a signed token instead of storing session data.
In Express, JWT is commonly used to secure APIs in MERN applications.

Stateless authentication means:

The server does not store any information about the user's login session. Every request contains all the information needed to authenticate the user.

🔹 High-Level Flow (Interview Ready ⭐)
Client → Login → JWT Issued → Store Token → Send Token → Verify Token → Access API

🔹 Step-by-Step JWT Authentication Flow
1️⃣ User Login

Client sends credentials:
POST /login

{
  "email": "user@gmail.com",
  "password": "123456"
}

2️⃣ Server Verifies Credentials
Checks user in DB
Compares hashed password

✔ If valid → generate JWT

3️⃣ Server Creates JWT
const jwt = require("jsonwebtoken");

const token = jwt.sign(
  { userId: user._id },
  process.env.JWT_SECRET,
  { expiresIn: "1h" }
);

JWT contains:

Payload (user info)
Secret key
Expiry

4️⃣ Client Stores JWT
Common options:
HttpOnly cookies ✅ (recommended)
LocalStorage ❌ (less secure)

5️⃣ Client Sends JWT in Requests

Using headers:
Authorization: Bearer <token>

Or cookies (with credentials: true).

6️⃣ JWT Verification Middleware
const auth = (req, res, next) => {
  const token = req.headers.authorization?.split(" ")[1];

  if (!token) return res.sendStatus(401);

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = decoded;
    next();
  } catch (err) {
    res.sendStatus(403);
  }
};

7️⃣ Protected Route Access
app.get("/profile", auth, (req, res) => {
  res.json({ user: req.user });
});

✔ Only accessible with valid JWT

🔹 Why JWT is Stateless (Important ⭐)
No server-side session storage
Each request carries auth info
Easy to scale (microservices)

🔹 JWT Structure (Must Know)
header.payload.signature

Example:
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

🔹 One-Line Interview Answer ⭐
JWT authentication in Express works by issuing a signed token after login, which the client sends with each request and the server verifies to authorize access without storing sessions.

22. ✅ What does stateless mean in JWT authentication?

Stateless means:

The server does NOT store any user session or login state.
Instead, all the authentication information is stored inside the JWT itself, and the client sends it with every request.

🔹 Stateful vs Stateless (Clear Comparison)
🔸 Stateful Authentication (Sessions)

Server stores session data (userId, role, etc.)
Session ID stored in cookies
Server must remember each logged-in user

Client → Session ID → Server
                ↑
           Session stored in memory / DB

❌ Harder to scale
❌ Needs shared session store (Redis)

🔸 Stateless Authentication (JWT)

Server stores no session
JWT contains user info + expiry
Token is verified using secret key

Client → JWT → Server
         (contains user info)

✔ No server-side memory
✔ Easy to scale
✔ Good for microservices

24. How do you protect routes in Express?

Routes in Express are protected using authentication and authorization middleware.
The middleware verifies the user’s identity (usually via JWT) before allowing access to the route.

🔹 Basic Idea (Interview Ready)

Check user → allow access → else block

🔹 Step-by-Step Route Protection Using JWT
1️⃣ Create Auth Middleware
const jwt = require("jsonwebtoken");

const authMiddleware = (req, res, next) => {
  const token =
    req.cookies?.token ||
    req.headers.authorization?.split(" ")[1];

  if (!token) {
    return res.status(401).json({ message: "Unauthorized" });
  }

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = decoded; // attach user info
    next();
  } catch (err) {
    return res.status(403).json({ message: "Invalid token" });
  }
};

2️⃣ Apply Middleware to Routes
Protect a Single Route
app.get("/profile", authMiddleware, (req, res) => {
  res.json({ user: req.user });
});

Protect Multiple Routes Using Router
router.use(authMiddleware);

router.get("/orders", getOrders);
router.post("/orders", createOrder);

✔ All routes in this router are protected

Improves API reliability

A middleware-based validation library.

const validateUser = (req, res, next) => {

29. What is clustering in Node.js / Express?

Clustering is a technique used to run multiple Node.js processes (workers) to fully utilize all CPU cores of a machine and handle more requests concurrently.
👉 By default, Node.js runs on a single CPU core.

🔹 Why Clustering is Needed

Node.js is single-threaded
Modern servers have multiple CPU cores
One process cannot fully utilize hardware

Clustering allows:
✔ Better performance
✔ Higher throughput
✔ Improved reliability

🔹 How Clustering Works (Concept)
Master Process
   ↓
Creates multiple Worker Processes
   ↓
Each worker listens on the same port
   ↓
OS load-balances requests

🔹 Simple Clustering Example
const cluster = require("cluster");
const os = require("os");

if (cluster.isMaster) {
  const cpuCount = os.cpus().length;

  for (let i = 0; i < cpuCount; i++) {
    cluster.fork();
  }
} else {
  const express = require("express");
  const app = express();

  app.get("/", (req, res) => {
    res.send(`Handled by process ${process.pid}`);
  });

  app.listen(3000);
}

🔹 What Happens If a Worker Crashes?

Master detects it
New worker is spawned
App continues running

✔ High availability

🔹 Clustering vs PM2 ⭐
Clustering	PM2
Native Node.js	Process manager
Manual setup	Automatic
Less features	Monitoring, restart
🔹 Important Interview Points ⭐

Uses multiple CPU cores
Each worker has its own memory
Not shared memory by default
Improves throughput, not single-request speed

🔹 One-Line Interview Answer ⭐
Clustering allows Node.js applications to run multiple worker processes across CPU cores to handle more concurrent requests and improve performance.
