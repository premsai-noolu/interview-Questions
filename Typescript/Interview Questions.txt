1. What is TypeScript? Why do we use it?

TypeScript is a superset of JavaScript that adds types.

👉 Why we use it:
Catches errors before running code
Improves code readability
Helps in large-scale applications

“TypeScript helps me write safer and more maintainable code by adding static typing on top of JavaScript.”

2. any vs unknown vs never in TypeScript
🟡 1. any (No type checking at all)

👉 any means:
“TypeScript, don’t check anything — I know what I’m doing.”

✅ Example:
let value: any = 10;

value = "hello";
value = true;

value.toUpperCase(); // ✅ No error (but risky!)
🚨 Problem:
Type safety is completely lost
Can cause runtime errors

👉 Example:

let value: any = 10;
value.toUpperCase(); // ❌ Runtime error (number has no toUpperCase)

🔵 2. unknown (Safe version of any)

👉 unknown means:
“I don’t know the type yet, but I will check before using it.”

✅ Example:
let value: unknown = "hello";

value.toUpperCase(); // ❌ Error

👉 You MUST check type first:

if (typeof value === "string") {
  console.log(value.toUpperCase()); // ✅ Safe
}
💡 Key Point:
Forces type checking
Prevents runtime errors

🔴 3. never (Value never exists)

👉 never means:
“This will NEVER happen.”

✅ Example 1: Function that never returns
function throwError(msg: string): never {
  throw new Error(msg);
}
✅ Example 2: Infinite loop
function infinite(): never {
  while (true) {}
}

3. What is type in TypeScript?

👉 type is used to create a custom name for any type
(primitive, object, union, function, etc.)

👉 Think of it like:
“A label for any kind of data structure”

🧱 1. Basic Type Alias (Simple)
type Name = string;

let userName: Name = "Prem";

👉 Here:
Name is just another name for string

🧩 2. Object Type
type User = {
  name: string;
  age: number;
};

const user: User = {
  name: "Prem",
  age: 22
};

👉 Same as interface, but written using type

🔀 3. Union Types (VERY IMPORTANT 🔥)
👉 Allows multiple possible values
type Status = "success" | "error" | "loading";

let currentStatus: Status = "success";

👉 Also:

type ID = string | number;

let userId: ID = 101;
userId = "abc123";

🔗 4. Intersection Types (Combine types)

👉 Combine multiple types into one

type Person = {
  name: string;
};

type Employee = {
  salary: number;
};

type Staff = Person & Employee;

const emp: Staff = {
  name: "Prem",
  salary: 50000
};

📦 5. Function Type
type Add = (a: number, b: number) => number;

const sum: Add = (a, b) => {
  return a + b;
};

📚 6. Array Type
type Numbers = number[];

const nums: Numbers = [1, 2, 3];

🎯 7. Tuple Type (Fixed structure)
type UserTuple = [string, number];

const user: UserTuple = ["Prem", 22];

👉 Order matters!

🧠 8. Advanced: Type Composition
type Address = {
  city: string;
};

type User = {
  name: string;
} & Address;

const u: User = {
  name: "Prem",
  city: "Vijayawada"
};

⚡ Key Advantages of type
✅ Can define:

Primitives (string, number)
Unions (A | B)
Intersections (A & B)
Functions
Tuples

👉 More flexible than interface
🚫 Limitation

❌ Cannot do declaration merging:

type User = { name: string };
type User = { age: number }; // ❌ Error
🎯 Simple Way to Remember

👉 type = “anything”
👉 interface = “mainly objects”

🔥 Interview Answer (Strong)

“Type in TypeScript is used to create custom type aliases. It is very flexible because it can represent primitives, unions, intersections, objects, functions, and tuples. I usually use type when I need advanced type compositions like unions or combining multiple types.”

4. What is interface?

👉 An interface defines the structure (shape) of an object

👉 Think of it like:
“A contract — if you follow this interface, your object must have these properties”

🧱 1. Basic Example

interface User {
  name: string;
  age: number;
}

const user: User = {
  name: "Prem",
  age: 22
};

👉 Rule:

Object must match the interface
Missing or extra properties → ❌ error
❌ Invalid Example
const user: User = {
  name: "Prem"
  // ❌ age is missing
};
🧩 2. Optional Properties

👉 Use ? when a property is not mandatory

interface User {
  name: string;
  age?: number;
}

const user1: User = { name: "Prem" };        // ✅
const user2: User = { name: "Sai", age: 22 } // ✅

🔒 3. Readonly Properties

👉 Cannot be changed after assignment

interface User {
  readonly id: number;
  name: string;
}

const user: User = {
  id: 1,
  name: "Prem"
};

user.id = 2; // ❌ Error

🔗 4. Extending Interfaces (Inheritance)

👉 One interface can reuse another

interface Person {
  name: string;
}

interface Employee extends Person {
  salary: number;
}

const emp: Employee = {
  name: "Prem",
  salary: 50000
};

🧠 5. Multiple Inheritance
interface A {
  a: number;
}

interface B {
  b: number;
}

interface C extends A, B {
  c: number;
}

const obj: C = {
  a: 1,
  b: 2,
  c: 3
};

🔁 6. Declaration Merging (VERY IMPORTANT 🔥)

👉 Same interface name → automatically combined

interface User {
  name: string;
}

interface User {
  age: number;
}

const user: User = {
  name: "Prem",
  age: 22
};

👉 This is NOT possible with type

⚙️ 7. Function Interface

👉 Interface can define function structure

interface Add {
  (a: number, b: number): number;
}

const sum: Add = (a, b) => a + b;

📦 8. Array Interface
interface StringArray {
  [index: number]: string;
}

const arr: StringArray = ["a", "b", "c"];

🔥 Interview Answer (Perfect)

“An interface in TypeScript is used to define the structure of an object. It acts like a contract that enforces what properties an object must have. It also supports features like optional properties, readonly fields, extension, and declaration merging, which makes it very useful in large-scale applications.”

5. 🔥 What are Generics?

👉 Generics allow you to write flexible and reusable code
👉 Instead of fixing a type, you use a placeholder type

👉 Think:
“I don’t know the type yet, but I’ll decide it later”

🧠 Why Generics?

Without generics ❌:

function identity(value: any) {
  return value;
}

👉 Problem:
Loses type safety
Returns any

With generics ✅:

function identity<T>(value: T): T {
  return value;
}

👉 Now:

Type is preserved
Fully safe
🧱 1. Basic Generic Function
function identity<T>(value: T): T {
  return value;
}

identity<string>("Hello"); // T = string
identity<number>(10);      // T = number

👉 T = placeholder (can be any type)

📦 2. Generic with Arrays
function getFirst<T>(arr: T[]): T {
  return arr[0];
}

getFirst<number>([1, 2, 3]);     // number
getFirst<string>(["a", "b"]);    // string

🔗 3. Multiple Generics
function pair<T, U>(a: T, b: U): [T, U] {
  return [a, b];
}

pair<string, number>("age", 22);

🧩 4. Generic with Interfaces
interface ApiResponse<T> {
  data: T;
  success: boolean;
}

const response: ApiResponse<string> = {
  data: "User data",
  success: true
};

👉 Real-world use: API responses

🏗️ 5. Generic with Classes
class Box<T> {
  content: T;

  constructor(value: T) {
    this.content = value;
  }
}

const numberBox = new Box<number>(10);
const stringBox = new Box<string>("Hello");

🎯 Interview Answer (Perfect 🔥)

“Generics in TypeScript allow us to create reusable and type-safe components by using placeholders for types. 
Instead of using any, generics preserve the actual type of data, making the code safer and more flexible. 
They are commonly used in functions, interfaces, classes, and API handling.”

6. keyof in TypeScript

👉 keyof gives you all keys of an object as a union type

🧱 Basic Example
type User = {
  name: string;
  age: number;
};
type UserKeys = keyof User;

👉 Result:
// "name" | "age"

✅ Usage Example
function printKey(key: keyof User) {
  console.log(key);
}

printKey("name"); // ✅
printKey("age");  // ✅
// printKey("salary"); ❌ Error

🧠 Why keyof?
👉 It ensures:
Only valid keys are used
Prevents mistakes

🔥 2. typeof in TypeScript
👉 typeof is used to get the type of a variable

🧱 Basic Example
const user = {
  name: "Prem",
  age: 22
};

type UserType = typeof user;

👉 Result:
// {
//   name: string;
//   age: number;
// }

✅ Usage Example
const count = 10;
type CountType = typeof count; // number

🚀 3. Combining keyof + typeof (VERY IMPORTANT 🔥)
👉 This is what interviewers love!

const user = {
  name: "Prem",
  age: 22
};

type Keys = keyof typeof user;

👉 Result:
// "name" | "age"

7. What is an Enum?

👉 An enum (enumeration) is a way to define a set of named constants
👉 Think:
“A group of related fixed values with meaningful names”

🧱 1. Numeric Enum (Default)
enum Status {
  Success,
  Error,
  Loading
}

👉 Behind the scenes:
Success = 0
Error = 1
Loading = 2

✅ Usage
let currentStatus: Status = Status.Success;
console.log(currentStatus); // 0

🔤 2. String Enum

👉 More readable (used in real projects)

enum Status {
  Success = "SUCCESS",
  Error = "ERROR",
  Loading = "LOADING"
}
✅ Usage
let status: Status = Status.Success;
console.log(status); // "SUCCESS"

⚙️ 4. Custom Values
enum Direction {
  Up = 1,
  Down = 5,
  Left = 10,
  Right = 20
}

🧠 5. Why Use Enums?
Without enum ❌:

let status = "success";

👉 Problem:

Typos possible
No autocomplete

With enum ✅:
let status: Status = Status.Success;

👉 Benefits:

Type safety
Auto-suggestions
No typos

🚀 6. Real-World Example
enum Role {
  Admin = "ADMIN",
  User = "USER",
  Guest = "GUEST"
}

function checkAccess(role: Role) {
  if (role === Role.Admin) {
    console.log("Full access");
  }
}

8. What is Type Assertion?

In short:
👉 Tell TypeScript what type it is
let value = "hello" as string;

👉 Type Assertion means:
“I know more about this value’s type than TypeScript does”
👉 You are telling TypeScript the type manually

🧠 Why do we need it?
TypeScript sometimes can’t infer the exact type
👉 Example:
let value: unknown = "hello";

👉 TS doesn’t know it’s a string → so this fails:
value.toUpperCase(); // ❌ Error

✅ Solution: Type Assertion
(value as string).toUpperCase(); // ✅

✌️ Two Syntaxes
1. as syntax (MOST USED ✅)
let value: unknown = "hello";
let str = value as string;

2. Angle-bracket syntax
let value: unknown = "hello";
let str = <string>value;

👉 ⚠️ Not used in React (JSX conflict)

📦 1. Example with DOM (VERY IMPORTANT 🔥)
const input = document.getElementById("username") as HTMLInputElement;
input.value = "Prem";

🔄 2. Example with API Data
type User = {
  name: string;
  age: number;
};

const data = JSON.parse('{"name":"Prem","age":22}') as User;
console.log(data.name); // ✅

9. ⚡ == vs === in JavaScript
🟡 1. == (Loose Equality)

👉 Compares values after type conversion (coercion)
👉 JS tries to convert types automatically

✅ Examples:
5 == "5"        // true  (string → number)
true == 1       // true
false == 0      // true
null == undefined // true

👉 Why?

JS converts "5" → 5
Then compares → equal
🔴 2. === (Strict Equality)

👉 Compares value + type (NO conversion)
👉 Types must be the same

✅ Examples:
5 === "5"       // false (number vs string)
true === 1      // false
false === 0     // false
null === undefined // false
